# 本轮实际浏览器操作

2026-09-12，Chromium，1440×960，管理员，enterprise UI。所有模型建议来自实际聊天，未用 API 预填建议。API 仅准备合成资料、独立工作区和回读结果。本文件是操作记录，不是完整控件覆盖声明。

1. 列表“开始建模”输入设备目标，创建任务，继续对话并发送任务恢复消息。DeepSeek 工具生成建议，未自动确认或发布。见 natural-conversation.json、natural-task.json。
2. 另建图书任务，选择 library-v1，失焦后保留选择；继续对话读取全部 224 码点。见 library-conversation.json、library-task.json。
3. 分别回答未决问题，确认建议。页面回到业务模型；独立回读验证 READY、ACCEPTED，编号实例没有成为模型类型。
4. 设备运行检查后发布。图书首次检查显示三项通过、资料需处理 22 条；进入参考资料，查看原始/当前全文，填写处理理由并逐条确认。重新检查四项通过后发布。来源确认不是跳过检查。
5. 设备版本应用到 T12 固定领域资料知识库。RDF/XML 原生下载后，经列表导入、预览、创建 T12 OWL往返验证草稿；规范 OWL 文本、摘要、22 条表达式集合相同。公理资源 ID 属于不同本体，不能直接比较 ID。
6. 设备知识工作台“业务对象”输入 urn:t12:equipment:P-101 和 P-101，显式添加实体；不指定直接类型。资料与证据选择 equipment-v1，保存原文版本。
7. 建模样例选择实际模型的第一个 P-101 样例，关联刚创建的实体，选择泵、equipment-v1 快照。输入不存在的摘录“原文没有这条结论”并失焦，提交审核禁用；改为“P-101是一台泵”后可以提交。
8. 独立回读此时 review=1、trusted=0。打开知识审核填写理由后确认；回读 trusted=1，r1 PROPOSED、r2 ACCEPTED，时间仍 UNKNOWN。审核详情和历史显示“类型：泵”。
9. 证据抽屉显示 equipment-v1 原文“P-101是一台泵”，码点 [97,106)，摘要与固定资料一致。见 sample-evidence.png、sample-accepted-readback.json。
10. 发布页刷新后，22 条来源规则显示图书、ISBN、借阅关系等业务名称，见 published-source-labels.png。

## 发现和修复

- 发布页未向来源面板传递投影，全部变成“扩展规则”。补传现有投影，实际刷新验证名称恢复。
- 样例类型下拉框、知识列表和审核详情显示哈希尾缀。复用现有 projectOntology 获取业务名称，声明仍使用原始 IRI。先运行名称回归得到失败，再修复到通过；没有引入依赖或替换页面布局。
- 自动化曾使用不存在的 tab/精确名称定位器、误选隐藏表单、在 HMR 重载后操作旧页签，导致超时；更正为实际可见控件并重做。它们未被记成产品功能失败。当前报告不声称全站无控制台错误。
