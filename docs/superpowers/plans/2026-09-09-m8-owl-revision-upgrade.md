# M8：已发布 OWL 修订之间的非空图升级

状态：实施规格，尚未验收。承接已授权的全量规划；VAL 的模型服务阻塞不改变其验收要求。

## 范围和约束

仅支持新 OWL 模型 v1→v2，目标必须是同一本体的已发布修订。旧格式数据由 RESET 清理，不提供转换入口。保持图、实体、事实及证据 ID 稳定；普通 rebind 仍禁止非空图。保留成熟工作台布局。

升级采用准备区和单事务切换。准备过程冻结源图版本、源和目标文档及 imports 摘要、实体和当前事实内容，生成目标解释下的暂存内容与影响报告，不修改在线图。任何未解决的映射或策略问题阻止批准。映射按 class/object property/data property/individual 区分，不能混淆同 IRI 的不同角色；通过标准 AST 改写，禁止文本替换。实体合并、拆分、单位换算、自动 sameAs 不在自动映射能力内，明确返回人工处理项。

批准由管理员显式操作，并绑定计划摘要。执行时锁定计划和图，重新核对图 mutationVersion、修订摘要、审核状态、来源依赖和待处理任务。所有实体索引、事实新修订、图本体绑定和升级审计在同一事务提交；失败保持源状态。准备和批准后有写入则 CAS 拒绝，不能覆盖并发工作。

每条当前事实追加目标本体下的新修订，保留原修订和原本体解释。实体旧 IRI、类型和显示名进入升级审计；IRI 交换必须处理唯一约束，禁止静默合并。证据及来源快照保持原引用。

回滚只允许升级后没有其他图写入的情况。回滚追加新的事实修订恢复源解释、恢复实体和图绑定并增加图版本；不得回退 current_revision 造成后续版本号碰撞。中间升级历史仍可查询。

## 文件与接口

新增 server semantic/graph/migration 服务、控制器、DTO、仓库及 V207 三库表；复用权限、版本序列化、操作幂等、标准公理验证。新增 UI 升级计划面板和 API。接口覆盖 prepare/get/approve/execute/rollback；每个写请求包含 operationId 和相应 CAS。不同载荷复用操作 ID 返回冲突。目标上限先沿用影响分析 1000 实体、10000 当前事实，并明确资源超限状态。

## 验收测试

1. 非空图 dry-run 不改变图、实体、事实；批准和执行后原子切换，旧事实修订仍绑定 v1。
2. 标准复杂类表达式、属性和个体映射使用 AST；punning 角色不串改；未知映射、重复目标实体或自动合并被阻断。
3. 新策略不满足、未提交抽取建议、未决候选/变更提案、M7 待复核及来源变化均阻止切换并给出原因。
4. 准备后并发事实写入、目标变化、撤权、不同载荷重放均拒绝；相同请求重放返回原结果。
5. 执行中故障整笔回滚；无并发写入可显式回滚，有并发写入拒绝；回滚后新增事实修订无主键碰撞。
6. imports 闭包变化进入计划摘要；跨工作空间、跨本体、未发布目标拒绝。
7. UI 切换工作空间不显示旧计划，明确人工批准和风险，API 与存储回读证明切换结果。

H2、隔离 MySQL 分别运行事务与迁移验证；没有 Kingbase 环境则记录未验证，不以兼容模式替代实库证明。
