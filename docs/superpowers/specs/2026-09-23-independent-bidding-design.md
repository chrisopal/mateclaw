# MateClaw 独立投标模块设计

日期：2026-09-23。状态：已完成源码级架构审查，按本文补充约束进入实施计划；尚未实施。审查结论与分阶段任务见 `../plans/2026-09-23-bidding-implementation.md`。

## 1. 目标与已确认决策

在 MateClaw 内建设投标业务模块，管理招标文件与技术标成果，派发本平台配置的数字员工执行解析、目录规划、写作、审核和导出。bid-agent 仅提供业务拆分与规则设计参考，不成为代码、数据、接口、部署或运行依赖。

| 事项 | 已确认选择 |
| --- | --- |
| 系统边界 | 本项目独立建设，与售前模块并列，复用 MateClaw 平台能力 |
| 数字员工 | 招标分析员、标书编写员、标书审核员三个岗位 |
| 流程 | 固定业务阶段，可配置执行员工与技能；关键节点人工确认 |
| 首版范围 | 技术标完整编制链路；商务要求仍解析并形成真实员工待办，不自动编写商务标 |
| 文件输入 | 可提取文字的 PDF、Word；扫描与不可读内容显式阻断，不静默遗漏 |
| 输出 | 每项 Skill 返回结构化内容，校验并持久化至数据库 |
| 重试 | 有限自动重试与人工重试结合，记录每次执行尝试 |
| 界面 | enterprise UI，六个业务页签，统一任务抽屉，简短中文标签与明确蓝色按钮 |

本规格为实现消歧补充的首版默认值，随全文一起审阅：Word 输入限定 `.docx`；正式交付以可编辑 DOCX 为必验格式，PDF 输出后续扩展；一个投标项目对应一个标段，未分标段时视为整体项目；自动重试最多两次；首版单应用实例调度。不得把这些默认值宣传为已实现能力。

范围之外：扫描件 OCR、商务标自动写作、自动报价、自动盖章或外部投标提交、可视化通用流程编辑器、多实例任务调度、整套 bid-agent 搬迁。所有“正式成果”均指技术标成果，不代表完整投标文件已经满足提交条件。

bid-agent 的流程定义、解析分类、行业提示词与证据约束作为只读参考。独立编写本项目的技能、Schema 与测试，不安装 bid-agent，不调用其接口，不读取其数据库，不绑定其路径或密钥。

## 3. 架构决策

### ADR-BID-01：固定流程与可配置岗位

选择固定业务流程，各项目为三个岗位选择平台中已有、启用且当前工作空间可用的数字员工。分析和编写岗位可使用同一员工配置，审核岗位必须绑定不同于编写岗位的员工；审核任务始终使用独立会话和只读输入。

备选方案是可配置流程模板，可适应更多流程，但首版需增加依赖编辑、非法循环、阶段门禁与模板升级治理。当前没有这项需求，推迟建设。完全依赖聊天推进不能提供明确业务状态、确认边界和可重复重试，不采用。

### ADR-BID-02：任务与成果分别持久化

数据库记录任务、尝试、输入快照、结构化结果、业务修订、人工决策和导出原字节。任务完成不等于人工采用，人工采用不等于阶段确认。长期执行不依赖浏览器连接或仅内存队列。

相较把所有内容塞入项目 JSON，独立任务/尝试记录增加少量表与迁移，但允许按任务恢复、分页查询、处理并发与重试；无需整项目改动就使无关任务失败。

### ADR-BID-03：重试与提交幂等

允许外部模型调用因网络结果不确定而再次发生；不承诺模型只执行或只收费一次。对本地成果保证同一尝试结果只提交一次，取消、过期执行和旧版本结果不能覆盖当前成果。失败状态与原因必须可回读。

### ADR-BID-04：售前通过版本交接

选择显式接收售前的已发布版本，独立保存交接快照和接收记录。不共享可变项目聚合，不把“最新方案”作为任务输入，也不把售前内部判断转成客户确认事实。直接新建投标项目不要求先有售前项目。

### ADR-BID-05：显式任务执行范围与固定技能包

现有售前执行隔离依赖 `presales:` 会话识别，技能工具默认读取活动版本。投标新增内部任务执行选项，向 AgentService、图构建和工具执行链传递服务端创建的尝试范围；普通聊天及售前旧接口保持兼容。不伪造售前会话，不只按会话名称判断授权。

派发时保存所用技能包的不可变内容，包括 SKILL.md、Schema 和该包的引用文件；记录版本与摘要。执行加载、子文件读取都从该快照读取，保存真实加载回执。每次尝试独立会话、禁用历史记忆注入，工具权限为员工有效授权与任务白名单的交集。业务确认、外部消息、任意命令及外部提交工具不在白名单中。模型、技能、工具授权等影响执行的配置使用不含密钥的配置指纹；变化后终止原任务重试并重新派发。

不建立第二套智能体运行栈，也不把库备份快照直接当作运行时固定版本能力。此选择增加少量平台接口，但避免静默换技能或跨任务读取。

### ADR-BID-06：只有任务调度层拥有自动重试额度

显式投标执行选项关闭模型客户端/流助手的自动重试及模型降级；工具循环中的正常模型调用不算重试，模型故障后不得再隐式请求。保留错误类别、Retry-After、部分输出、停止和结果未知标志，调度器据此处理。只有完整正常结束、实际技能加载成功且通过校验的输出才能提交为有效成果；不能把部分 JSON 或错误提示文本当成成功。

### ADR-BID-07：完整读取与受控文档生成

现有 TikaExtractor 的长度上限可能返回截断文本，MarkdownDocxRenderer 可读取本地图片路径，不能不加约束直接用于招标输入和正式成果。使用现有 PDFBox/POI 建立带覆盖清单的受控读取与结构化 DOCX 渲染入口。超限、未知嵌入内容和不能可靠定位的表格必须明确阻断或标记待人工核对，不返回伪完整结果。

长文件按稳定区块分片；四项分析分别以“技能 × 分片”形成子任务，成功分片保留，失败分片独立重试。确定性合并只去除同来源同定位的重复项，跨来源矛盾交由人工处理。服务器核对计划区块、实际读取回执与结果覆盖；不相信模型单方面声称已读完。导出只消费结构化内容和授权图片字节，禁止任意路径、URL、HTML 或代码。

## 4. 岗位、流程与确认

真实负责人从工作空间真实成员中选择；数字员工只承担执行岗位，没有阶段确认、最终批准、商务承诺或外部提交权限。

| 阶段 | 执行与产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 项目准备 | 上传原文、附件、补遗，选择员工，可接收售前成果 | 来源可读、版本清楚、权限和必需技能可用 |
| 招标解析 | 分别生成基础信息、废标项、需求、评分项 | 四类结果均有效；人工处理未决冲突、确认解析基线 |
| 目录规划 | 生成章节树、条款与评分映射、材料清单 | 人工确认目录版本；强制目录和必须响应的技术条款已安排 |
| 技术标写作 | 分章执行、引用授权材料、保存草稿和缺失项 | 已有选定的整本版本；缺失项显式可见 |
| 审核与修订 | 审核员产生问题清单，编写员针对选定问题修订 | 人工接受修订，受影响内容重新审核 |
| 审定与导出 | 先生成并检查候选 DOCX，再由人工审定具体文件 | 审定绑定候选原字节和输入版本，正式下载发布同一组字节 |

派发一次解析任务组后，四项分析基于同一生效来源清单，可独立执行；需求分析不以基础信息候选成功为硬前置；任何一项失败不重做其他成功项。人工确认解析基线后按预先批准的流程自动派发目录任务；确认目录后可批量派发写作，候选整本写作完成后自动派发审核。发现需要补充材料或人工决策时暂停受影响任务。

审核意见不会自行应用到正文：真实员工选择需要修改的问题后派发修订，修订形成候选版本；接受修订后再次审核，避免无限自动往返。模型无权关闭人工待办。

正式审定要求当前整本版本完成审核，且没有未处理的技术阻断项：强制技术条款未响应、必需证明缺失、无依据承诺、来源不可读或版本冲突。真实员工可以对误报作有证据的驳回并留痕，但不能以笼统“接受风险”代替缺失的强制材料。一般改进建议可注明暂不采纳；商务待办按其是否影响技术内容决定是否阻断技术标审定。

解析基线、目录、整本正文均有“候选、已确认/已审定、需重新确认”状态。项目显示当前可推进阶段，不根据模型自由返回的阶段字段跳转。没有当前有效确认时，后端拒绝越级命令。

商务事项独立列为真实员工待办。技术标可单独形成正式成果，商务待办不能因此自动关闭；影响技术方案的商务条件或资格事实缺失时，相关技术章节仍须阻断或标为待补充。

## 5. 文件、补遗与证据

1. 每次上传保存来源身份、文件类型、原始字节、大小、摘要与不可变版本；重新上传不覆盖历史。接受 `.pdf`、`.docx`，其他格式给出明确错误，不假装已解析。
2. 受控工具先提取文字、表格和稳定段落/区块标识，再调用技能分析。PDF 证据记录实际 PDF 页序和区块；DOCX 使用标题路径、段落或表格单元格位置，不虚构页码。
3. 逐页/区块记录可读性。扫描 PDF、混合 PDF 中不可读的实质内容、加密或损坏文件须提示问题；没有文本不能推断“没有需求”。人工可排除确认无业务内容的封面/空白页并留原因，不能豁免实质招标内容。原图、嵌入对象无法解释时显式列为待核实。
4. 同一项目可含原文、附件和多份补遗，来源清单由人工确认。补遗不直接覆盖原条款；分析员输出新增、修改、取消及冲突建议，人工确认其生效范围。
5. 生效来源集变化会使引用旧内容的结果、确认和审核标记需复核；未完成影响分析前先保守阻断新正式导出。系统比较结构化引用，重新确认未受影响部分后可保留，不强制重写整本。
6. 来源内容属于不可信数据，不能提升工具权限、改变技能输出契约或执行文档中的指令。原文中的外部链接不自动联网访问。

所有证据引用使用来源版本与定位标识；展示的摘录必须匹配本次读取的原文。模型置信度仅供排序，不替代证据校验或人的判断。

## 6. 八项技能及结构化输出

每项技能独立维护 `SKILL.md`、输入/输出 Schema、参考规则和脱敏测试样例。技能 ID 为内部稳定标识，页面只显示简短中文名称。技能由项目岗位绑定的员工真实加载执行，并在尝试记录中保存所用版本与内容摘要；不能仅在页面标示技能名称，实际用另一套内嵌提示词代替。

| 内部技能 ID | 岗位 | 核心输入 | 结构化 payload 必备内容 |
| --- | --- | --- | --- |
| `bidding-tender-profile` | 分析员 | 生效来源集、读取区块 | `basicInfo`（项目、招标人、标段）、`deadlines`、`deliveryConditions`、`mandatoryOutline`、`formatRequirements`、`unknowns` |
| `bidding-elimination-analysis` | 分析员 | 生效来源集 | `items`：原文否决条件、适用范围、触发条件、待核实项、证据；不把所有“应/须”自动判为废标项 |
| `bidding-requirement-analysis` | 分析员 | 生效来源集；基础信息候选仅作可选上下文 | `requirements`：类型、原文要求、约束、验收条件、技术/商务归属、歧义及证据 |
| `bidding-scoring-analysis` | 分析员 | 生效来源集 | `criteria`：层级、分值、规则、证明要求、证据；`totalChecks`：可计算汇总与原文总分的差异 |
| `bidding-outline-planning` | 编写员 | 已确认解析基线、可用材料清单 | `chapters`：层级、标题、写作要求、强制目录引用、需求引用、评分引用、所需材料；`unmappedItems` |
| `bidding-technical-writing` | 编写员 | 已确认目录、指定章节、条款与授权材料；修订时附正文版本和选定问题 | `chapter`：章节引用、结构化内容块；`responses`、`citations`、`missingMaterials`、`unresolvedItems` |
| `bidding-technical-review` | 审核员 | 解析基线、目录、选定整本正文和证据快照 | `findings`：严重性、问题类型、章节/条款定位、证据和建议；`coverage`、`limitations`；不返回批准决定 |
| `bidding-document-export` | 编写员 | 确定正文版本、模板版本、格式要求、预览/待审定候选模式 | `artifactManifest`：文件标识、类型、字节数、内容摘要、正文/模板版本；`checks`：生成与结构检查结果 |

每条事实或问题都有稳定的项标识和引用。模型输出中的临时项标识由服务器校验后映射到数据库对象；不能由模型指定 Workspace、操作者、批准人或可写对象范围。未知值使用明确的空值和原因，不补造日期、分值、资质或案例。

分析技能必须返回分析覆盖范围和未处理来源。空列表只有在全部指定来源读取完成且明确报告未识别到该类条目时才是有效候选；结构正确不意味着语义完整，仍需人工确认和真实样例验收。

### 6.1 公共执行信封

由服务端组装并持久化，不信任模型返回的身份和状态字段：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion / skillId / skillVersion / skillDigest` | 契约与实际执行技能身份 |
| `workspaceId / projectId / taskId / attemptId / actorId / agentId` | 受服务端控制的执行范围和追踪标识 |
| `inputSnapshot / inputDigest / inputRefs` | 完整输入内容或可稳定解析的不可变内部对象，以及源版本引用 |
| `payload / warnings / evidenceRefs` | 经过相应技能 Schema 校验的结构化结果 |
| `validation / error / startedAt / finishedAt` | 校验结果、分类错误与执行时间 |

通过结构校验之后，还需检查引用存在、属于当前范围、来自输入快照、无循环目录、分值可计算规则与文件摘要等确定性约束。语义判断交给员工与人工复核，不以 JSON 校验通过冒充业务通过。

验证失败时保存受权限保护且限长的拒绝输出和错误位置，不创建有效业务成果。日志只记录诊断标识，禁止写入密钥或完整敏感正文。员工的中间聊天不替代结构化结果持久化。

### 6.2 写作、检索与导出的职责

写作按章节建立任务，批量写作是任务组，不把整本无限长度正文塞进一次模型调用。章节内容采用有限的标题、段落、列表、表格与授权图片引用结构，不执行任意 HTML。单章超出输出限额时明确失败并允许拆分章节，不能保存截断结果为成功。

知识库命中只作为候选材料：读取和引用时检查权限、内容版本、有效性与适用范围。售前结论不能自动变为本次技术承诺。审核采用独立输入和会话，不依赖编写员的聊天记忆。

导出技能负责依据已选模板调用受控生成与校验工具，不重写正文，不返回任意命令、路径或下载地址。导出器根据内容/模板版本生成 DOCX，平台对实际原字节计算摘要，并从已验证产物构造返回信封；模型声明“已导出”不足以成功。

生成先保存候选原字节并完成内容与结构检查，真实员工预览或下载候选后，再执行最终审定。人工决定同时绑定候选产物 ID、字节摘要、正文版本、模板版本及格式要求。正式下载只是对同一组已批准字节开放正式成果状态，不再调用模型或渲染器；重复下载返回同一产物。后台审定与发布均重查输入版本、权限和技术阻断项。

变更模板、正文、附件或重新渲染为不同字节必须产生新候选并重新审定，不沿用旧批准。一般预览稿可单独标示草稿；用于最终审定的候选必须采用最终文件样式，通过界面标记“待审定”，不能在批准后以去水印等理由修改字节。生成工具只能创建候选，不能创建人工批准决定或自行发布。

## 7. 持久化与并发边界

以下为逻辑实体；具体迁移编号、索引与 Java 类型在实施计划中确定，沿用项目现有数据库方言，不新增数据库产品。

| 实体 | 必存内容 |
| --- | --- |
| 投标项目 | Workspace、项目/标段、真实负责人、岗位绑定、阶段、乐观版本、当前选定修订 |
| 来源修订 | 原始字节、来源类型、摘要、读取区块、质量状态、版本及补遗关系 |
| 业务修订 | 类型、稳定对象 ID、版本、结构化 JSON、输入引用、作者/任务来源、内容摘要、候选/确认/失效状态 |
| 任务 | 业务动作、目标章节或整本、输入快照、执行员工/技能/模型配置标识、状态、操作幂等键、取消状态 |
| 执行尝试 | 任务、尝试序号、执行令牌、起止时间、完整结构化结果或拒绝输出、错误、下一次执行时间 |
| 人工决策 | 真实操作者、决定、理由、精确结果/内容/模板/格式版本与摘要、最终审定的候选产物 ID 与字节摘要、时间、失效原因 |
| 交接接收 | 售前项目、发布/基线/方案精确版本、交接快照摘要、接收项目、真实接收人和时间 |
| 文件产物 | 正文与模板/格式版本、模式、格式、摘要、实际原字节、生成尝试、检查结果、正式发布关联的人工 DecisionRef |
| 操作记录 | Workspace、操作者、幂等键、请求摘要、操作结果、时间 |

所有技能的结构化输出保存在数据库，即使尚未被人工采用也可查看。任务与尝试分别存储，不把重试写成覆盖原错误记录。常用状态和范围作为可查询列，技能差异化数据存版本化 JSON；不为每个技能新建一套任务表。

单次结果提交事务包含：校验当前执行令牌和任务状态 → 保存尝试结果 → 创建候选业务修订/文件产物 → 更新任务终态。任一步失败全部回滚；恢复后明确显示中断或存储错误。

限制同一任务仅有一个活动尝试；同一尝试仅有一次成果提交。同一操作幂等键加相同请求返回原结果，不同请求返回冲突。批量章节按各自对象版本处理，不用整项目版本阻止无关章节并行完成。

人工编辑保存新修订，不覆盖模型候选。候选只能通过版本比较后被采用；旧任务结束时如输入依赖已变化，保存诊断并标记结果过期，不更新当前正文。正文有未采用的候选不自动替代已选择版本。

## 8. 调度、自动重试与恢复

任务状态至少包括排队、执行中、等待重试、成功、失败、已取消、结果过期。业务“等待人工确认”属于业务阶段，不把已成功的任务长时间标为执行中。

### 8.1 执行规则

- 创建任务与输入快照在同一事务提交，再由数据库中的待执行记录驱动后台领取；请求快速返回任务标识。排队记录由周期扫描兜底，避免“落库成功但入内存队列失败”永久丢失。
- 首版只允许一个应用实例负责调度，使用有界线程池、任务原子领取与执行令牌；扩展多实例前需另行设计租约。慢模型调用期间不持有数据库事务。
- 初次执行与重试都重新校验发起人的当前权限、员工可用性、技能版本和来源可读权限。管理员触发人工重试时记录新的实际发起人，不能复用过期请求线程身份绕过校验。
- 确认解析、目录等业务动作与创建后续待执行任务原子提交，自动推进不会越过人工节点。

### 8.2 自动重试

- 首版每轮最多执行三次：一次初始尝试、两次自动重试。默认间隔为 10 秒、30 秒并附少量抖动；有 `Retry-After` 时至少等待其指定时间。任务保存 `nextRunAt`，等待不占工作线程。
- 仅允许明确识别的连接故障、限流与可恢复服务端故障自动重试。不得把权限失败、模型未配置、工具审批等待、Schema/引用失败、输入过期、材料不足、不可读文件统称为网络错误。
- 响应超时且外部结果不确定时记录该事实；本模块允许再次执行的工具仅能读取授权来源或幂等生成内部候选，不能自动发送外部消息或执行提交动作。
- 结果已收到而仅数据库提交失败时，先重试同一次本地提交，不能立即再次调用模型。进程崩溃且未存下结果时显式记录结果未知，之后由人工重试，不伪装成已恢复输出。
- 自动重试沿用同一输入快照和技能版本。运行配置或输入版本变化时停止自动重试；修复配置后人工重新派发新任务，并关联原任务。

### 8.3 人工重试、取消与重启

- 自动重试耗尽或可人工处理的失败，显示“重试”或“处理后重新执行”，并说明原因。相同输入/配置下人工重试关联原任务，创建新尝试并重置本轮自动重试额度；历史尝试总序号持续递增。
- 修改招标文件、目录、章节输入或模型/技能配置后，创建关联原任务的新任务，不冒充原输入重试。若固定版本技能已不可用，停止并提示重新派发。
- 取消立即持久化并禁止新尝试，尽力停止外部调用；迟到返回由执行令牌拒绝，不产生可采用成果。不承诺取消后供应商立即停止计费。
- 服务启动时恢复已到期排队/重试任务；上次进程遗留的执行中尝试转为“执行中断”，留待人工重试，不无条件重复模型调用。旧执行令牌不可再提交。
- 重试只作用于失败项：评分项解析、单个章节、审核或导出各自独立；已成功的兄弟任务继续保留。

## 9. 售前衔接与权限

投标可以直接新建。由售前创建时，真实员工选择有权访问的已发布方案版本，预览交接内容后明确接收。交接内容包含需求基线、方案、可授权读取的证据引用、范围、风险与未决问题，不转移批准权限或客户确认身份。

接收时必须校验发布版本及文件摘要，保存不可变交接快照与接收记录；接收幂等键防止重复点击创建相同目标。一个售前项目可以关联多个独立投标项目，每个项目代表一个标段。售前功能关闭或交接权限不足时，直接新建路径仍可用。

现有 `handoff` 需通过窄接口扩展为显式版本选择与接收快照，不能把当前可变澄清混入历史发布事实；如纳入接收时新增信息，应另列为接收时注记并注明时间和来源。后续售前更新仅提示变更，不自动更换投标任务输入。

Workspace 是首版授权边界，不声称提供尚未实现的项目私有权限。查看者可读其授权范围内的业务记录；成员可上传、派发、编辑；项目真实负责人或工作空间管理员可确认和审定。负责人必须是当前有效真实成员，权限在后端判定，不由前端隐藏按钮代替。

读取任务、诊断、引用、快照和下载文件均重新鉴权；来源授权撤销后，相关快照、派生成果和下载需重新校验并阻止未授权访问，不能因复制成内部 JSON 绕过原材料权限。数字员工使用任务范围与自身工具授权的交集，不接受模型自行扩大范围。

## 10. 页面与交互

入口为投标工作台。列表显示项目、标段、真实负责人、阶段、截止时间和待处理数量，支持搜索、筛选与分页；简洁统计展示在办项目、临近截止、待确认和失败任务数量，统计口径与列表权限一致。临近截止定义为未来 7 天内，已过期单独标识；未知时间不计入。无数据时不回填演示记录。

| 页签 | 主操作与内容 |
| --- | --- |
| 项目概览 | 负责人、三个员工岗位、截止时间、当前阶段、待处理事项、售前来源 |
| 招标文件 | 原文、附件、补遗与版本；查看原文、派发解析、处理读取问题 |
| 招标解析 | 基础信息、废标项、需求、评分项分类查看；证据、修订、人工确认解析基线 |
| 标书目录 | 强制目录要求、章节树、覆盖关系；调整和确认目录 |
| 技术标写作 | 左侧章节树、中间正文、按需展开证据；分章/批量生成、候选比较、修订与采用 |
| 审核与导出 | 问题与整改、审定、预览稿和正式成果；商务待办保持可见但不混入正文 |

统一任务抽屉展示输入版本、执行员工、技能版本、状态、尝试次数、结果和重试操作。详细诊断、结构化原始结果和日志按需展开。字段与按钮用业务中文，不显示 G1/G2、Fit-Gap 或裸 ID；人员选择器显示姓名。

操作按钮有明确边界与蓝色视觉，表格操作列按统一宽度/间距排列，不因换行错位。页内不铺设重复说明文字。证据与诊断通过抽屉查看，长标书不与密集统计挤在同一屏。兼容既有主题，不无意改变售前页面。

必须覆盖空、加载中、无权限、配置缺失、部分失败、输入过期、读取不完整、并发冲突、等待确认及重试中的状态。页面刷新后以数据库为准恢复任务和选定版本。

## 11. 验收标准

所有实现阶段分别记录代码检查、数据库回读、浏览器交互和真实模型证据。未运行项目记录 NOT_RUN；静态测试通过不能代替真实员工和文档验收。

| 编号 | 必须证明的行为 |
| --- | --- |
| A01 独立运行 | 停止 bid-agent 后仍完成流程；配置和运行路径不依赖其地址、目录、数据库或包 |
| A02 员工技能 | 三岗位使用所绑定员工，八项技能有独立 Schema；尝试记录可核对实际技能版本与输出 |
| A03 原文解析 | PDF/DOCX 样例四类分析均结构化入库并可回读；引用能定位到正确原文，表格与数字不丢失 |
| A04 不可读来源 | 扫描/混合不可读页、损坏和加密文件明确失败或阻断确认，不能返回伪完整空列表 |
| A05 流程门禁 | 未确认解析不能正式规划后续目录，未确认目录不能进入批量正文写作；直接 API 调用同样受限 |
| A06 输出拒绝 | 畸形 JSON、缺字段、跨项目引用、不存在证据和目录循环不生成有效成果，可查看拒绝原因 |
| A07 重试 | 临时故障最多两次自动重试，等待时间和次数可回读；永久错误不自动重试；人工重试保留历史 |
| A08 幂等与并发 | 重复派发、重试、回调及确认不重复产出；单章失败不重做兄弟章节，人工编辑不被迟到结果覆盖 |
| A09 恢复与取消 | 模拟任务落库后入队失败、服务重启、执行超时和取消，状态有明确终态或可恢复入口，无长期假运行 |
| A10 更新影响 | 补遗、目录或材料版本变化会标记相关结果失效；旧版本不能通过正式导出门禁 |
| A11 技术标审核 | 审核问题有章节/条款定位；接受修订后旧审核不能直接沿用；AI 不能批准、关闭人工待办或补造资质 |
| A12 导出 | DOCX 可打开且正文、表格、目录、分页和证据选用经人工检查；审定记录的产物摘要、数据库原字节与正式下载摘要一致；审定期间改版或重新渲染不能继承批准 |
| A13 售前交接 | 独立建项和已发布售前版本接收均可完成；重复接收幂等、越权拒绝、源更新不覆盖已接收版本 |
| A14 权限 | 跨 Workspace 读取、任务/快照查询、证据及文件下载被服务端拒绝；执行前后撤权均测试 |
| A15 UI 回读 | 新建、配置岗位、解析确认、目录确认、章节修订、重试、审核、审定、下载及刷新回读在真实浏览器通过 |
| A16 完整业务样例 | 至少一份脱敏真实可读招标样例由真实模型完成技术标全流程；黄金条款、评分、废标项由人工标注核对，报告遗漏与误判 |

数据库写失败、模型限流、Schema 错误、过期输入和服务重启使用可控故障注入验证。真实模型测试记录来源样例、配置标识、任务和尝试、成果修订及摘要，禁止保存密钥。测试环境不得混入生产项目或伪造批准记录。

## 12. 运行边界与容量默认值

下列数值是本次架构审查提出的首版可配置保守默认值，不是实测性能承诺。实施时通过样例与压测记录调整依据：单文件 25 MiB、单项目生效来源合计 100 MiB、单 PDF 500 页、单来源提取文本 1,000,000 个 Unicode 码点、单分析分片 12,000 个码点（表格不静默切断）、单次结构化输出 2 MiB。超限返回明确错误，禁止自动截断。

单实例最多 2 个活动尝试、每工作空间最多 1 个；调度扫描间隔 2 秒、每次最多领取 20 项。单尝试总时限 300 秒，工具/模型循环最多 12 轮；到限保留诊断并失败，章节过大通过人工调整目录后重新派发处理。手动重试可开启新一轮，但不隐藏累积尝试和模型用量。

技能包与业务对象按确定性编码计算 SHA-256，所有时间以 UTC 持久化、按用户时区展示；招标截止时间保留原始文字与原时区，时区不明确时不进入确定截止统计。金额、分值用十进制和单位，API 不以浮点数悄悄四舍五入；人员及数据库长整数 ID 以字符串返回前端。

提供排队数、最老排队时间、尝试耗时、错误类别、模型用量、结果未知次数与取消后迟到返回计数；指标不含正文和密钥。所有源字节、技能包、输出与派生文件纳入同一备份与恢复演练，首版不自动清理历史版本。单实例是部署约束，不能把 JVM 内线程池当作多实例防重保证。

## 13. 交付顺序与剩余风险

整体目标始终是完整技术标链路，按三个可验收阶段编制实施计划，各阶段单独列任务与验证证据：

1. **项目到解析基线**：项目/标段与岗位、文件及版本、任务/尝试/重试公共能力、四项解析 Skill、来源证据、人工确认；交付一条可从页面发起并刷新回读的真实解析链路。
2. **基线到技术标草稿**：售前版本接收、目录规划确认、材料选择、单章及批量写作、候选采用和补遗影响；交付可追溯的整本技术标正文。
3. **草稿到正式技术标成果**：独立审核、问题修订、审定、DOCX 导出、格式验收和完整真实样例回归；达到 A01–A16 的整体交付标准。

实施前先验证现有文档提取工具的 PDF/DOCX 定位与表格质量、技能加载链路及实际数据库迁移约束；不把接口存在等同于可直接满足需求。若能力不足，优先补强本项目现有工具，新增依赖需按项目约束单独确认。
