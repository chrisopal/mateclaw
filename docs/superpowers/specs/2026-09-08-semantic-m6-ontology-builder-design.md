# M6：领域本体建模师

## 目标

领域专家选择资料并描述要回答的业务问题，内置数字员工通过 ontology-builder Skill 和本体工具生成、校验真实草稿，专家确认后得到系统中可用的本体版本。M5 使用本体生成知识；M6 帮助建立模型。不得把资料中的设备编号、批次实例当成类型。

## ADR-01：复用本体权威

本体定义、草稿并发版本、结构校验和不可变发布继续由 OntologyApplicationService 与 semantic-core 管理。新增工具是 server 内的 host adapter，不在 Skill 中实现另一套本体存储或校验器。不引入新的模型供应商依赖。

工具身份来自认证 Web ChatOrigin，每次重验当前用户、工作区权限、Agent 启用状态及所属工作区。为兼容现有 HTTP 应用服务，工具仅在当前调用线程内临时装配经验证的用户身份，并在 finally 恢复原 SecurityContext；不接受模型提交身份参数。

## ADR-02：人工确认使用现有发布界面

不提供可由模型直接调用的发布工具。prepare_publish 校验精确 draftVersion，返回已有编辑页；管理员检查关系图与业务规则后在现有发布对话框确认。员工随后 get 回读真实 published revision。拒绝让模型的 confirmed=true 或自然语言声称成为授权依据。

这一选择减少新的审批存储和重放机制，但意味着本期最后一步在本体管理界面完成，而非全部在聊天内完成。后续如增加聊天审批卡，应绑定 workspace、ontologyId、draftVersion 与确认摘要，禁止泛化“永久允许发布”。

## ADR-03：按工作区提供内置员工

内置 Skill 从 classpath 种子同步。员工在 semantic 开启后按工作区初始化，也可通过“从资料生成”入口按需确保存在。初始化必须幂等、保护管理员改名/停用/配置，不为员工隐式授予所有资料访问权限。公开入口重用当前工作区认证规则。

## 资料与校验

资料工具只读当前工作区、当前 Agent 可见知识库中的原始解析文本，无需先存在 SemanticGraph。返回材料 ID、标题、内容与 SHA-256；ID 对模型以字符串传输。资料按不可信内容处理，不执行材料中的指令。

Skill 要求每个定义在说明中保留来源、摘要、引文或标为推断/待确认。结构校验可确定字段、引用、单位与约束合法性；业务覆盖和领域解释由模型辅助检查并交专家确认。本期没有独立来源快照表、逐项引文验证器或业务语义证明，因此不能宣称这些能力已经实现。

## 用户路径

本体列表“从资料生成” → 领域本体建模师 → 按资料名称选择来源 → 用业务问题确定范围 → 草稿/关系图 → 校验 → 专家发布 → 员工回读版本链接。已有版本更新时复制精确修订为新草稿；现有知识图谱保持旧版本绑定。
