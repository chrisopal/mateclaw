# 本体管理界面与配置维护规格

日期：2026-09-05。状态：Proposed，已纳入用户要求的首期交付范围；页面和 API 尚未实现。

## 1. 产品定位

在现有 MateClaw 企业工作台增加“本体管理”，让管理员能够通过表单创建和维护本体、配置实体类型/属性/关系、保存草稿、校验、对比并发布新版本。用户无需编辑 Java、数据库或配置文件完成正常维护。

领域边界沿用[领域模型](2026-09-05-semantic-domain-model.md)：本体管理规则，知识库管理资料，语义图管理实例事实。本体编辑器不承担具体设备、合同或事实值的编辑。

首期沿用 Vue、Element Plus、当前登录/工作区和企业主题；功能目录建议为 `mateclaw-ui/src/features/semantic/ontology/`。这是当前应用内的正式管理功能，不单独建设控制台。

## 2. 页面与入口

顶层在现有知识相关导航附近新增“本体管理”，建议路由 `/semantic/ontologies`；从具体知识库的语义图区域提供“查看所用本体”入口，跳到绑定的精确版本。现有 Wiki 路由保留。

| 页面/区域 | 显示与操作 | 用户完成的工作 |
|---|---|---|
| 本体列表 | 名称、说明、当前可选发布版本、是否有草稿、可见绑定数量、最后维护人/时间；搜索、新建、打开 | 找到并管理当前工作区的本体 |
| 本体详情 | 概览、实体类型、属性、关系、校验结果、版本历史、绑定情况 | 理解和维护一套业务定义 |
| 草稿编辑 | 从空白新建或从某个已发布版本建立草稿；保存、校验、预览差异、发布 | 安全修改配置 |
| 版本历史与对比 | 版本、发布时间、发布人、变更说明；选择两版对比新增/修改/移除定义 | 追踪变化、核对旧版本 |
| 校验及发布面板 | 定位到字段的错误、警告、差异、基于哪版、发布说明与影响提示 | 发布前发现问题 |
| 知识库绑定区域 | 是否启用语义图、绑定本体和版本、查看定义、可选版本与限制说明 | 明确图采用哪套规则 |

图谱/事实/证据查询和事实审核沿用整体语义模块的交付范围。本体管理不替代它们；两个界面通过版本和引用导航连接。

## 3. 编辑器结构与字段

建议采用“页面标题和操作栏 + 定义分类列表 + 表格/表单编辑区”，通过 Tab 切换类型、属性和关系。新增/编辑一项定义用现有 Drawer；先以表单和表格提供完整维护能力，不引入拖拽画布依赖。

| 配置对象 | 可编辑内容 | 交互约束 |
|---|---|---|
| 本体基本信息 | 名称、说明、发布说明 | 本体身份不可通过改名称替换 |
| 实体类型 | 类型编码、中文名称、说明 | 编码唯一；已发布内容只能在新草稿中修改 |
| 属性定义 | 属性编码、名称、所属类型、值类型、单值/多值、适用时的固定单位 | 所属类型和类型值通过下拉选择；只展示当前模型支持的字段 |
| 关系定义 | 关系编码、名称、起点类型、终点类型、单值/多值 | 起终点必须是当前草稿已定义类型；数量约束明确为从起点出发 |

值类型仅展示 TEXT、DECIMAL、BOOLEAN、DATE、INSTANT 的中文标签，保存严格类型值。首期不展示未实现的继承、推理规则、复杂约束或本体导入包设置。

删除被属性/关系引用的草稿类型时，展示引用列表并阻止保存不完整定义；用户必须显式调整引用，不自动级联删除其他配置。草稿可以尚未完整但保存结构必须合法；发布要求所有领域校验通过。

## 4. 从维护到发布的完整流程

```text
新建本体 / 打开已发布版本
→ 建立草稿
→ 配置类型、属性和关系
→ 保存草稿
→ 校验并定位修正
→ 查看与基准版本的差异
→ 填写发布说明并发布
→ 服务端重新校验、原子保存发布版本
→ 回读发布结果及精确版本
```

保存草稿不发布，也不改变任何正在使用的图谱。已发布版本只读，页面主操作为“建立新版本草稿”，不提供原地编辑入口。

同一本体首期最多一个活动草稿，多人维护采用乐观并发校验。草稿保存带 expectedDraftVersion；冲突时保留本地编辑内容，提示其他人已更新并允许重新载入/对比，不采用静默最后写入覆盖。

校验报告必须标记所检查的 draftVersion。保存新修改后旧报告显示过期；发布端必须在事务内再次校验最新草稿和 expectedDraftVersion，不能依赖前端绿色图标。发布请求带幂等标识，网络结果不明确时先查询结果，避免重复生成版本。

## 5. 更新、生效、停用与恢复

- 已发布 v1 上维护时产生新草稿，发布为新版本；列表区分“最新发布版本”和“该知识库实际绑定版本”。
- 新发布版本可供新图选择，已有图继续绑定原精确版本。发布结果明确提示“已发布；原有图谱保持各自绑定版本”，不得显示“所有知识库已更新”。
- 空图可显式换绑；绑定提交时服务端重新检查权限、版本状态和图是否仍为空，避免并发写入绕过限制。
- 有数据的图首期不提供直接换绑。页面显示当前版本、可见新版本及“已有事实，需要本体迁移流程”的具体原因。完整迁移是后续独立能力，不以这个按钮冒充已实现。
- “停止供新图使用”只影响新绑定选择，既有图仍可读取所需历史版本。不能删除已被引用的发布版本。
- 恢复旧配置通过“从历史版本建立草稿并发布新版本”完成；历史不改写，也不自动迁移已有图。
- 草稿放弃有明确提示；本期不提供本体级不可逆级联删除。

这里把“修改本体配置”与“迁移已存在的事实图谱”区分开。如果后续要求同一已有图持续采用更新规则，需要显式增加兼容性分析、重验证和迁移验收。

## 6. 权限与工作区切换

建议在现有 capability 机制增加 `view:ontology`、`manage:ontology`、`publish:ontology`，沿用既有角色而不新增权限中心：viewer 可读、member 可维护草稿、admin/owner 可发布和停止新绑定；图的启用/换绑同时检查 KB 管理权限，首期限定 admin/owner 操作。

这是待实现的角色映射，不是当前已有能力。后端返回的权限是前端显示依据；API 必须再次检查工作区和对象归属。拥有本体可读权限不等于可查看全部绑定知识库，绑定列表及数量只包含有权访问的资源。

切换工作区或离开脏表单前处理未保存修改；取消旧请求，响应按工作区隔离；不能把旧工作区的本体和草稿写入新工作区。只读页面不显示可操作的保存/发布按钮，直接调用 API 同样拒绝。

## 7. 对模型和 API 的补充

复用既有 Ontology/OntologyRevision；草稿补充 baseRevisionId、draftVersion、updatedBy/At。draftVersion 用于编辑并发，独立于本体发布 version，不混用两个编号。

发布版本具有供新图选择的治理状态，内容保持不可变。发布说明、发布人、时间和基准版本须持久化；版本对比按稳定类型/属性/关系编码执行，避免把显示名称变化误认为新增对象。

宿主应用服务需提供：

1. 列表、详情和精确版本读取；
2. 新建本体、建立/读取/保存/放弃草稿；
3. 草稿校验及版本差异；
4. 幂等发布、发布结果查询、停止新绑定；
5. 按资源权限过滤的绑定查询、启用图和空图换绑。

Web DTO 和 JSON 序列化属于 Server；纯 Java 核心只处理定义、校验和版本不变量。不得为管理界面把 Spring 或前端结构引入核心。错误采用稳定错误码与字段路径；前端显示可操作的中文说明，不展示堆栈。

## 8. 与现有 UI 的关系及取舍

保留现有 MainLayout、Wiki、工作区切换、Element Plus、API Client、i18n 和主题。新增独立页面及最少路由/菜单挂接，不替换现有业务页面，也不引入第二套组件框架。

复用已落地的 `--mc-*` / Element Plus tokens 和企业样式适配：列表采用过滤栏加表格，编辑采用表单和 Drawer，状态用文字加提示色；不重新全局改色。classic 与 enterprise profile 均可访问被授权的功能，外观开关不承担权限开关。

独立控制台会重复身份和导航；拖拽编辑器会扩大开发及验证范围。首期选择表格/表单，在能够准确维护配置后再考虑只读结构预览或更复杂编辑方式。

本次为信息结构与交互规格，未声称新页面已渲染或通过视觉验收。视觉实施前需记录当前界面基线，完成后检查双 profile、浅深色、桌面/窄屏、键盘焦点及表单可用性。

## 9. 首期交付门禁

验收必须通过真实管理界面完成，不以 Postman、配置文件或 Mock 页面代替：

- 新建一个本体，配置至少两个类型、一个属性和一个关系，保存并刷新后回读一致。
- 缺失目标类型、重复编码、错误值类型等校验失败可定位到具体项；服务器拒绝绕过校验发布。
- 发布 v1，刷新仍可见；发布版本不可直接编辑。
- 从 v1 建立草稿、修改并发布 v2，能查看准确差异和发布记录；v1 保持原样。
- 图绑定 v1 后发布 v2，回读仍绑定 v1；空图换绑成功，非空图换绑被拒绝并显示原因。
- 并发保存、重复发布、校验报告过期、发布响应不明均不造成覆盖或重复版本。
- viewer 不能修改，member 不能发布；跨工作区访问和绑定拒绝，绑定统计不泄漏隐藏 KB。
- 完成类型检查、相关前后端测试与构建，并提供认证浏览器的编辑/发布/回读证据；相关数据库未运行则单列兼容性缺口。

这组管理能力是整体 S3 的必交付项。只完成核心、API 或只读图谱，不满足用户此次要求。
