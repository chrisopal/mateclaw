# 给其它前端项目的 AI 实施提示词

将整个 `enterprise-ui-standard` 目录复制到目标项目后，使用下面的提示词。根据实际任务选择“先出方案”或“按已确认方案实施”，不要让规范本身扩大任务范围。

```text
请以本项目中的 enterprise-ui-standard/README.md、tokens.json、tokens.css 和 CHECKLIST.md 为企业 UI 规范。

目标：让本项目前端遵循同样克制、扁平、统一的企业工作台风格，不照搬任何来源产品的品牌和业务内容。

先检查真实工程：框架、现有组件库、主题 Token、公共框架、典型页面、路由/权限/数据流和已有测试。先说明保留、替换、移除项及风险，不直接重写整个前端。

必须遵守：
1. 单一蓝色体系、蓝灰中性色、细边框、轻层级。正文默认14px，控件4px圆角，面板6px圆角。
2. 品牌蓝、交互文字蓝、实心按钮背景分别消费语义 Token；深色按钮与文字、反色提示的颜色必须成对校验。
3. 普通容器和按钮不使用装饰渐变、毛玻璃、光晕、厚重阴影、呼吸或卡片上浮。经确认的品牌3D图标是局部例外。
4. 复用现有框架、组件库和公共组件，不新建平行UI体系，不擅自增加依赖。
5. 保留本项目名称、Logo、菜单、业务流程、API、权限、路由、缓存、国际化与数据契约。
6. 通过主题映射和有明确作用域的适配层实施；不要使用全局所有button/svg/div等选择器覆盖专业内容。
7. 检查body浮层、错误/禁用/加载/空状态、键盘焦点，以及现有浅色/深色模式。
8. 分阶段验证共享框架、样板页和专业工作面；在1366/1440/1920/390px检查真实渲染。
9. 运行项目已有的lint、typecheck、tests和build；以截图和真实交互复验，不以绿色测试数量代替视觉或业务验收。
10. 交付时列出改动文件、实际验证证据、例外、未测试范围和回退方法。不要未经要求提交、推送或部署。

本轮任务：先出方案（若已有批准的实现计划，则改为“按该计划实施”）。
本轮范围：填写目标页面或模块。
```

如果 Codex 已安装 `mbc-enterprise-ui` 技能，可以用更短的方式：

```text
使用 $mbc-enterprise-ui，并以 enterprise-ui-standard 中的通用规范和语义 Token 为基准。
先审视本项目现有前端，给出最小改造方案；保留本项目品牌、业务逻辑和组件库。
```

此目录不依赖该技能安装，也不要求连接原始 Figma 文件；如果要求像素级复刻另一个具体页面，应另外提供该页面的设计稿与截图。
