# T06 logical consistency check UI blueprint

## Scope

Add one compact logical check section to the existing ontology editor's
`检查发布` tab. The section invokes `POST /semantic/ontologies/{id}/draft/reason`
with the current `expectedDraftVersion`, renders consistency using business
labels, and keeps structural validation and the T07 publish gate independent.

## Visual thesis

Use the existing flat release checklist: one calm status row with a single
accent action, a small result block only after a run, and the same spacing,
border, typography, and responsive rules already used by `OntologyEditor` and
T05 business rules.

## Content and interaction

- Label the section `模型逻辑检查`; explain that it checks logical
  satisfiability for the saved draft and does not replace structural checks.
- Show `未检查`, `检查中`, `未发现逻辑矛盾`, `模型存在矛盾`, or `未能完成检查`
  from the response's `consistent` value. A consistent result with
  `unsatisfiableClasses` is shown as `存在无法成立的对象类型`; names use the
  standard projection's friendly labels.
- Surface explicit `timeout`, `error`, `unsupported`, `stale`, and `cancelled`
  states. Cancellation stops waiting for the response and says the server may
  still be processing; it never claims that the worker stopped.
- Invalidate and clear results when workspace, ontology id, draft version, or
  dirty state changes. Late responses are accepted only when their scope and
  captured draft version are still current.

## API and timing

The API wrapper preserves the captured workspace header and sends
`{ expectedDraftVersion }`. Its Axios timeout is bounded above 30 seconds so a
long-running reasoning worker can finish (`120_000ms`); the UI does not add a
shorter timer.

## Acceptance gates

- Missing `consistent`/`null` is shown as unable to establish; `false` is shown
  as contradiction, including friendly unsatisfiable class names.
- Save/dirty/structural validation/publish behavior remains unchanged.
- Component tests cover true/false/null results, friendly labels, cancellation
  and late responses, version invalidation, and explicit error states.
