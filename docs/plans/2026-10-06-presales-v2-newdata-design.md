## 方案与取舍

采用现有售前用例、UI 和权限链上的新数据存储升级。拒绝另起一套工作台/API（重复权限和生成执行平台），拒绝只改项目版本判断（仍保留整项目持久化权威）。新创建项目声明 V2 存储格式：项目行仅元数据，各类对象独立行和不可变修订；业务读取临时组装响应，数据库中没有第二份可写聚合。不回填旧项目，不自动用旧 JSON 接管 V2。项目事务锁可串行化写入，但不作为模型输入的业务依赖版本。

### 职责和数据

- Repository 负责 SQL/事务内事实，独立纯编解码器分拆/组装材料、需求、澄清、基线、fit、案例、方案及章节、评审、发布、任务等对象。只对变化对象新增修订。已有单个不可变文档/发布快照仍允许 JSON。
- 项目 metadata、对象当前版本和不可变修订只有一个写入路径；快照/回执按精确修订引用回放。无新旧双写，无启动回填。
- Task 记录实际读取的对象版本及来源摘要；捕获后无关档案编辑不使任务过期。新增/删除/修改实际读取的集合成员或选定方案/章节使结果明确 stale，不能自动采用。排队、工具调用前及结果接纳均核验。
- 收尾在短事务内锁定并重读当前项目，只合并任务及生成结果，保留并行档案修改。员工/角色/Workspace/资料撤权、attempt 和取消规则保持。
- Delivery 接收明确 projectId/releaseId/digest，通过公开售前应用接口读取、校验并持久化冻结 handoff；禁止 latest 漂移。新接收、回读、重复接收及异摘要拒绝用真实数据库/API验证。不扩展排期/工单等无关 Delivery 功能。

### Delivery 新消费契约

所有请求必须带 `X-Workspace-Id` 和当前用户身份。`GET /api/v1/delivery/handoff-preview?projectId=...&releaseId=...` 返回精确已发布版本的 `snapshotJson` 和 SHA-256 `digest`。`POST /api/v1/delivery/handoffs` 接收 `operationId/projectId/releaseId/digest`，在独立短事务内持久化；`GET /api/v1/delivery/handoffs/{id}` 回读同一冻结数据。相同 actor/Workspace/operation 的同请求（包括并发）返回同一记录，异请求冲突；回放和读取仍复核当前来源权限。身份、Workspace、来源错误通过领域公开接口传递，不依赖其他业务模块内部异常。

V2 所有业务与工具入口必须经 `PresalesProjectRepository` 读取组装视图；不直接将项目表 `body_json` 当完整业务聚合。数据库里只保留元数据和不可变对象修订引用，HTTP 响应仍可由只读组装返回已有业务字段。

### 新写入故障与回退

事务失败不留下对象修订、项目版本或操作回执的部分提交。V2 写入后不切回聚合 JSON；回退采用保留 V2 数据的前向修复/隔离恢复策略，明确拒绝不支持 V2 的写入路径。不实施旧数据反向转换。

### 真实生成质量

用全新隔离 Workspace/项目和获授权真实模型，走生产员工/Skill/异步任务/审批/发布/Delivery 链路。验证完整结构、来源定位、需求覆盖、长文截断提示、事实/未确认内容区分、真实输出文件可读与摘要、独立内容评审。模拟模型仅用于可重现回归，不作为真实生成完成证据。模型凭证不出日志；生产数据不写。
