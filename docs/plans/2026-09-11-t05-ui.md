# T05 Business rules UI blueprint

## Scope

Add a top-level `Business rules` tab to the existing ontology editor workspace. The
view edits persisted business policy metadata and checks a sample against the
current draft. Existing graph, OWL text, axiom, navigation, and publication
flows remain unchanged.

## Visual thesis

Calm, flat enterprise workbench: a dense two-column policy workspace on desktop,
collapsing to one readable column on narrow screens, using the existing semantic
surface, border, typography, and blue action tokens without decorative cards or
new visual chrome.

## Content plan

- Context: one short sentence and selected business class; retain the editor saved status without technical version identifiers.
- Rules: a table/list of data-property rules showing friendly class/property
  names, required, single value, unit, datatype, and enum summary; add/edit and
  remove actions are adjacent to the list.
- Sample: a compact form for one class and its properties. Each property accepts
  multiple newline-separated lexical values, optional units, and a complete or
  partial submission mode. Results show validity and field-level violations.

## Interaction thesis

- Rule add/edit uses a compact responsive dialog; it keeps the selected class and
  data-property context visible and prevents accidental loss on cancel.
- Saves use one stable operation id per attempted command and lock policy edits,
  sample checks, navigation, and other draft actions until an ambiguous save is
  recovered or resolved. A retry replays the exact body.
- Any draft, workspace, class, property, or sample-input change clears stale
  sample results; loading and error state always identify the current action.

## Acceptance gates

- PUT business-policy body contains `operationId`, `expectedDraftVersion`, and
  the complete rule set; a successful response replaces draft/projection state.
- POST check-sample body contains draft version, class IRI, complete/partial
  mode, and typed literal rows; results are accepted only for the current draft
  and current sample input.
- Rules preserve unrelated classes when editing one rule; add, edit, remove,
  required/single/unit/enum behavior is visible and keyboard accessible.
- No copy claims reasoning or publication validity; sample validity is scoped to
  business-policy conformance.
- Desktop and narrow responsive layouts remain free of page-level horizontal
  overflow; existing model graph responsive behavior is preserved.
