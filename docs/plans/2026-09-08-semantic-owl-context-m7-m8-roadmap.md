### VAL-01：质量案例对照与通用性验证

主场景：三坐标测量异常。模型覆盖设备、测头、测针配置、测量程序版本、测量任务、工件 / 特征、装夹 / 基准、环境观测、测量结果、调查假设与验证记录；这些都是领域配置。

必须区分实测偏差与公差标准：合法的超差实测值可以保存，系统另行判断合格状态；不能把业务不合格误当数据不能录入。多候选原因不自动互斥，只有领域规则明确时才建立排他约束。

对照三组：A = 术语说明 + 文档 / 事实检索；B = A + 本体上下文；C = B + 形式推理。保持模型及版本、题集、资料、工具数据权限、输出要求和评审标准一致，记录上下文选择、实际 token 和端到端延迟；使用重复运行避免凭单次输出判断。

题集覆盖：同义词、类型 / 实例混淆、关系方向、跨程序 / 时间配置、未知值、多个假设、超差事实、证据冲突、来源撤回和公理分类。由领域专家制定期望结论 / 允许的未知答案；合成样本验证结构，真实资料用于证明实际应用价值。

评价：概念与事实错误、因素覆盖、应追问信息、无依据结论、引用正确性、成本和延迟。所有权限 / 事实治理反例须通过；若 B / C 无收益或发生回退，记录失败并修正，不预设“OWL 一定更高效”。数值效果门槛在运行前根据基线冻结，避免看到结果后改标准。

第二场景：小型库存可用量解释，用不同本体、资料与样本验证无需修改核心代码；不扩展为库存事务系统或排产求解器。本体独有价值与普通配置价值分别记录。

- 先试运行和人工复核映射，再批准真实迁移。推荐评估准备区构建后原子切换的方式，具体物理模型在 M8 设计时确定；不直接 UPDATE 绑定号。
- 迁移保留新 OWL 体系产生的历史修订、源 OWL 定义解释、证据和审计；派生结果重算；事实冲突通过治理流程，不由迁移脚本擅自选择赢家。本次允许清理旧测试数据，不代表未来版本升级可直接删数据。
- 检测 M5 待提交建议、M7 未完成复核和正在写入的事务；执行前重新核对版本，提供明确写入协调、幂等、失败恢复与兼容回退策略。
- 切换后更新 CTX 可见版本与缓存。支持报告不充分或迁移中断时，旧可用状态不能变成半迁移状态。

验收：成功升级、不可兼容变更拒绝、陈旧批准、并发写入、断电 / 重启恢复、重复执行、前后查询和证据、H2 / MySQL 真实回读、备份恢复与兼容回退；没有 Kingbase 环境时单列未验证。

## 5. 执行顺序与阶段边界

主顺序：G0 → OWL-01 → OWL-02（含 RESET 与新用例重建）→ OWL-03 / CTX-01 → VAL-01 → M7 → M8。

- OWL-03 与 CTX-01 只在接口稳定后允许独立部分并行；正式对照验收依赖两者。
- M7 对来源依赖的契约可在 OWL-01 预留，避免后来改写本体权威；本次不提前实现整个更新系统。
- M8 设计参考 M7 队列、OWL 影响语义及真实样例，确保处理进行中的复核和抽取任务。
- 下一次仅交付 OWL-01。用户确认该单元的架构、依赖及实施范围后，执行 OWL-02；不能以这份路线建议自动跨越全部阶段。
