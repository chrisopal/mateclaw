# T06：精确草稿逻辑检查

已完成。本批基线 `51d61805`，不包含 T07 统一检查报告和服务端发布门禁。

## 实现

- 新增 `POST /api/v1/semantic/ontologies/{id}/draft/reason`，要求成员权限与期望草稿版本。
- 固定文档、锁定导入、策略与检查配置；短事务获取快照，事务外运行已有受限 HermiT 子进程，结束后重新检查授权及输入。变化返回 `REASONING_STALE`。
- 检查模型及其导入中的个体断言，不混入知识库事实，不创建正式图、发布版本或修改草稿。
- 独立报告整体一致性与不可满足命名类别；超时、失败、不支持、取消均不能误判为通过。
- 现有“检查发布”页加入逻辑检查。业务对象名称优先，技术诊断折叠；停止等待不会声称终止服务器进程。草稿、工作区变化会清理旧结果。
- 删去结构检查区“推理尚未执行”的固定文案，避免与独立逻辑检查状态冲突。

主要文件：`DraftReasoningService.java`、`OntologyController.java`、`OntologyDtos.java`、`ReasoningResult.java`、`HermitReasoningWorker.java`、`LogicalConsistencyPanel.vue`、`OntologyEditor.vue` 及 API 类型和对应测试。
