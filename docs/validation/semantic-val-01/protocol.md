# VAL-01 运行前协议

状态：输入准备中，未完成真实模型对照。现有 gptsapi 默认模型连接检查返回 HTTP 401 / Balance is insufficient；检查请求不是正式题集实验。

采用已冻结 context-contract 的三组：A=相同资料与已审核事实；B=A+自然语言领域摘要；C=A+应用实际生成的版本固定本体上下文及正式推理输出。主路线早期建议中的另一套 A/B/C 命名不与本次混用。C 衡量结构化上下文与逻辑工具的组合效果，不能把差异全部归因于 OWL 文本格式。

18 题（质量12、库存6）、每组每题3次，共162次。questions.json 的问题、expected、forbidden 不修改。先通过真实应用接口在隔离 H2 中建模、保存、发布、绑定、导入快照、建立证据、提出并审核事实；通过实际 ContextService 与 HermiT 导出输入，禁止手填推理成功。所有样本为已标注合成资料，只验证结构和方法，不证明真实工厂效益。

所有组使用相同 provider/model、temperature=0、max_tokens=900、输出格式、题目和资料权限。输入文件、自然语言摘要、题集、脚本及模型设置的 SHA-256 写入运行 manifest，运行中变化则拒绝恢复。请求顺序固定随机种子20260909打散；已有成功结果不重复计入，失败结果保持独立记录。不得把模型超时、拒绝或余额不足记作知识错误。

共同输出为 JSON：answer（中文）、citations（所给证据ID数组）、unknowns（缺失信息数组）。记录原始回答、模型回报的版本名称、usage（未提供时为null）、模型 HTTP 请求往返延迟、请求摘要；不记录凭据。延迟不包含预先执行的上下文检索、导出与推理，不能称为完整业务端到端耗时。评估时间与观测时间分开，历史快照不冒充实时状态。

C 使用预先生成的有预算上限的完整夹具上下文。本轮衡量回答效果和模型输入开销，不证明按问题自适应检索的速度或大规模本体效率。

运行前验收门槛：

- 所有组的引用ID必须来自提供的证据，非法引用数为0；无引用不可假称已验证。
- C 的版本引用错误及证据误引必须为0；C 的无依据根因断言不得多于 A/B。
- 准确性、因素覆盖、应追问信息和因果断言由隐去组别的复核包逐项判断；程序仅检查引用ID/JSON和汇总usage、p50/p95，不能代替专家盲评。
- 不预设 B/C 更好；若成本上升而准确性无改善，记录不通过价值验证，后续调整检索并单独记录新实验，不能改本轮评分标准。
- 未提供真实计费明细时只报告实际 token 用量，不估造货币成本。模型别名不能保证服务端权重恒定，回报版本变化需分组标记。

当前验收缺口：可用模型账户、实际162次结果及人工盲评。真实工业材料属于后续外部有效性验证；本轮已确认的质量与库存合成用例不替代该结论。脚本完成或合成数据导出成功不等于 VAL-01 验收通过。
