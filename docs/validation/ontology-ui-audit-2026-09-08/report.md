# 本体管理前端企业风格审核

日期：2026-09-08。对象：semantic-m1 工作树的现有本体管理与知识工作台。性质：只读审核；本轮仅新增本报告、截图与字体测量证据，未修改业务代码或业务数据。

## 结论

现有蓝灰配色、扁平容器、表格和表单具备企业产品基础，建议保留。主要差距是标题层级、图中文字阅读尺度，以及知识核对流程的信息优先级。更换字体本身不能解决这些问题。当前不建议将界面一致性标记为已验收。

未在本次覆盖状态发现阻断操作的 P0；发现四项应优先处理的 P1，以及三项 P2。这里只评价所观察状态，不代表所有功能、权限或无障碍状态通过。

## 问题、根因与验收

### P1-01：模块标题与正文几乎同级

证据：步骤 2、3、6。测量显示页面标题为 20px/600，而“版本 v1”“对象关系图”“比较版本”等标题为 14px/400、行高 21px。不同语义层级缺乏可见区分。

定位：`mateclaw-ui/src/features/semantic/ontology/semantic.css` 仅统一页面 h1；`OntologyVersions.vue` 的 h2/h3，以及 `components/OntologyStructureGraph.vue` 的 h3 未完整定义大小和字重。

建议：在 semantic 模块内统一模块标题 16px/600、行高 24px，保留页面标题 20px/600；用 16–24px 模块间距建立层级。避免覆盖宿主所有 h2/h3。

验收：列表、编辑、版本、工作台的同级标题样式一致；深浅主题均能区分标题、正文、辅助信息。

### P1-02：关系图自动适配压缩文字，信息虽然显示却难以阅读

证据：步骤 2、3，画布当前显示 78% 缩放。SVG 类型名 14px、属性 12px、标识 10px，缩放后约为 10.9、9.4、7.8px；关系标签样式为 11px，同样受缩放影响。右侧无选择详情仍固定占 300px，进一步压缩画布。

定位：`ontology/components/OntologyStructureGraph.vue` 的 `.structure-layout`、节点与边文字样式。

建议：区分“总览”和“阅读”模式；总览保留类型与关键关系，选中后以正常字号显示完整属性、约束和关联。提供明显的 100%/适应画布切换；未选择时详情区可收起或显示紧凑说明。不可仅通过放大所有节点导致连线拥挤。

验收：在 1366、1440、1920 宽度下，完整关系与属性都有易发现的阅读入口；阅读态关键文本至少 12px，详情正文 14px；缩放、选择与拖动画布仍可用。

### P1-03：已提交知识以禁用表单呈现，结果难读

证据：步骤 4。已有提交记录的字段为低强调禁用控件，业务对象名称混入长数字 ID；仍有选择提示和禁用操作，用户难以判断是在查看结果还是继续填写。

定位：`extraction/SuggestionReviewPanel.vue` 的只读表单分支与对象标签。

建议：只读记录使用正常对比度的字段值列表，显示提交状态和“查看已提交知识”入口；业务名称优先，ID 放入次级详情/复制入口。编辑态继续沿用现有表单，保持权限和提交规则不变。

验收：已提交、待核对和不可编辑三种状态清楚区分；只读内容无需点击禁用控件即可看全；不开放原本禁止的修改操作。

### P1-04：窄屏当前标签不可见，实际核对内容落到首屏之外

证据：步骤 5，390×844 页面未出现整体横向溢出，但当前“从资料生成”标签在横向标签栏可见范围之外。资料核对区域顶部约为 884px。桌面步骤 4 中长任务说明也占据较大高度。

定位：`graph/SemanticWorkbench.vue` 标签容器；`extraction/ExtractionTaskPanel.vue` 无折叠的 explanation；`ExtractionWizard.vue` 的介绍、任务历史及建议选择区。

建议：当前标签切换后滚入可见范围；窄屏可采用明确的当前模块选择器。任务概况压缩为状态、资料名、处理数量与操作；长模型说明默认折叠并保留展开入口。优先露出建议选择和资料核对。

验收：390px 宽当前模块始终可识别，无整体横向滚动；进入已有任务后首屏可见下一步核对入口；长文本展开不会遮挡主要操作。

### P2-01：版本操作分组不明确

证据：步骤 3 版本标题、禁止新绑定、导出三个直接子项被分散排列；步骤 6 返回、历史、丢弃、保存、校验、发布六个按钮竞争注意力。

定位：`OntologyVersions.vue` 版本头部与 `semantic.css` 的 `justify-content: space-between`；`OntologyEditor.vue` 页头。

建议：标题与操作组两端对齐；低频操作收进“更多”，危险操作单独分隔；草稿保留保存/校验/发布的明确阶段关系。

验收：不同标题长度、窄窗口下按钮分组保持稳定；丢弃操作与常用保存操作有明确区别。

### P2-02：同一流程混用原生选择器与组件库选择器

证据：步骤 3、4 的画布/任务选择器与表单 Element Plus 控件在外观、交互表达上不同。源代码确认原生 select 分别维护 padding、边框、圆角。

定位：`OntologyStructureGraph.vue`、`ExtractionWizard.vue`，对比 `SuggestionReviewPanel.vue`。

建议：复用现有项目控件与尺寸规范；若画布保留原生控件，需统一字重、高度、焦点、禁用态及下拉指示，不增加新的组件依赖。

验收：同一工具栏的按钮与选择器高度一致；键盘聚焦可见，长选项能读取；深浅主题均检查。

### P2-03：任务状态和导航缺少业务语境

证据：步骤 4，模型生成完成标签仍表达“待核对”，而当前已有全部提交记录；顶部面包屑出现“MateClaw / MateClaw”。长英文模型解释也与中文管理界面语境不一致。

建议：模型执行状态与人工处理进度分别展示，使用真实建议状态统计；面包屑显示知识库/图谱名称及工作台位置。原始模型解释放入可展开详情，不把执行成功等同于人工审核完成。

验收：生成完成但未核对、部分提交、全部提交显示正确；从工作台可识别当前图谱与返回路径。

## UI Blueprint：后续统一规范

视觉方向：沿用现有企业主题，以蓝色表达可操作/选中状态，以灰阶建立信息层级，语义色仅用于成功、警告、错误。保留扁平表格与右侧编辑抽屉，不增加装饰性横幅、渐变或卡片堆叠。

| 对象 | 建议规范 |
|---|---|
| 字体 | 沿用现有 Inter / 系统字体 / PingFang SC / Microsoft YaHei 栈；本次只验证计算样式，未证明实际加载 Inter |
| 页面标题 | 20px / 600 / 行高 30px |
| 模块标题 | 16px / 600 / 行高 24px |
| 正文与字段值 | 14px / 400 / 行高约 22px |
| 标签与辅助说明 | 13px；表头和次级元数据可 12px，不用低对比度代替层级 |
| 控件 | 常规约 34px 高；优先复用项目现有尺寸 token，触屏入口另检查点击范围 |
| 布局 | 页面边距沿用桌面 24px、窄屏 16px；4px 间距基准；主要模块间距 16–24px |
| 表面 | 保留既有边框和 4–6px 圆角，不引入第二套颜色 token |
| 对比度目标 | 正常文本至少 4.5:1；关键控件边界/状态至少 3:1；逐项测量后再声明通过 |

内容结构：列表保持“筛选—表格”；版本页采用“版本信息—关系画布—选中详情—比较/使用情况”；编辑页保持“基础信息—类型/属性/关系—校验”；工作台采用“紧凑进度—建议选择—来源与核对并列”。窄屏按任务顺序堆叠。

交互方向：只保留功能性展开、选择、聚焦和抽屉反馈；不添加装饰动画。缩放与选中不能丢失阅读位置，只读结果不伪装成不可操作表单。

实现边界：样式及展示逻辑限制在 `mateclaw-ui/src/features/semantic/`，复用宿主主题变量与组件。保持语义核心、服务端 API、权限、版本冻结与知识提交规则不变；不为视觉统一重构 MateClaw 原生页面。

建议实施顺序：第一批统一标题、只读结果、任务说明折叠和当前标签可见性；第二批调整画布阅读模式与详情布局；第三批收敛操作组、选择器和导航文案。每批按上述截图对应的真实状态回归，避免只用空数据页验收。
