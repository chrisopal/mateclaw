## 结论

M5 主线已实现并在真实宿主运行：资料→固定快照/本体/模型→生成建议→人工映射和核对→原有 PROPOSED→管理员审核→原有可信查询。新增 `mateclaw-semantic-application` 只依赖 JDK/core；模型、数据库、授权及 MateClaw API 适配在 server。没有新增第三方依赖或第二套审核权威。

真实质量主线使用 `deepseek-chat`，最终任务 `9445e9aa-691a-4fce-a09b-5e07f60568c2`，1次尝试生成4条建议，无引文/本体诊断；经人工映射审核后，查询返回4条 ACCEPTED/r2/有证据支持的知识。数据库回读确认任务 SUCCEEDED、4条建议及4张提交收据，服务重启后保留。该次模型用量为输入551、输出730 tokens，来自持久化 attempt；不能将错误尝试中未取得的用量视为实际零消耗。

## 操作与回退

默认 `mateclaw.semantic.extraction.enabled=false`。本地18088仅通过启动参数开启；5176为enterprise验收界面。关闭辅助生成阻止新任务与模型执行，已有人工知识功能继续可用；重新启动服务时历史任务/收据保留。不要删除已有迁移或以改V197校验和回退。恢复到旧应用前应单独备份数据库并评估兼容性。

本期边界：只支持现有WIKI_RAW解析资料，一任务一份资料；不自动登记/合并对象，不自动批准、不抓取外部来源。宿主目前使用其现有启用聊天模型列表，未新建按工作区分配模型的权限系统；如部署需要更细模型使用策略，应在宿主适配层补齐。
