# M6 验证记录

状态：实现完成，本地运行及合成资料端到端验收通过。本记录随实现提交 Git；未部署远端。

## 实现与边界

内置“领域本体建模师”绑定 ontology-builder 与 OntologyAuthoringTool。模型可以读取授权资料，创建、保存和校验草稿；准备发布返回现有编辑页面，由具备权限的用户在发布对话框确认。聊天中的自然语言确认不作为服务端发布授权。既有知识图谱不自动换绑。

本次复用现有本体应用服务、事务、权限、版本比较及发布界面，没有新增依赖或独立发布引擎。工作区员工初始化可重复执行，保留管理员已有编辑和禁用配置，不自动授予所有知识库。

主要变更：authoring/OntologyAuthoringTool.java、authoring/OntologyBuilderProvisioning.java、web/OntologyBuilderController.java、内置 ontology-builder/SKILL.md、三种数据库的 V198 工具注册迁移，以及 OntologyList.vue 的“从资料生成”入口、API 和中英文文案。新增工具、技能、初始化和入口测试；共享 H2 测试基类关闭后台抽取调度，避免跨上下文抢占测试任务，生产调度不变。

## 剩余能力与环境限制

- 结构校验不证明业务语义正确。实例报告中的 mm 单位和单台设备不能直接证明整个领域都采用固定单位或单值加工关系；本例在发布说明中明确仅供测试，业务使用前必须由专家确认。
- 当前来源 ID、哈希与引文保存在定义说明中，由 Skill 要求核对；没有独立的不可变资料快照、逐字段引文验证器或自动覆盖率证明。
- 资料发现最多 20 个授权知识库、每库 50 份资料；单份资料最多 100000 字符。大型资料分段与跨批次建模尚未实现。
- 新建草稿响应不确定时需先查询并恢复，当前没有独立的模型请求幂等键。
- MySQL/Kingbase 运行迁移尚未实测；真实模型只验证一个合成案例，不代表各领域建模质量已全面验收。
