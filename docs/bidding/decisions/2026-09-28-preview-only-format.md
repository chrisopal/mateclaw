# ADR: 将内部预览与正式候选的格式门禁分开

状态：已采纳（P3 导出纵向切片）

## 背景与约束

实际模型从招标文件提取的强制格式包含“可编辑 DOCX”“最多三级标题”“目录与页码”等复合要求。当前受控渲染器无法证明目录条目有页码，因此正式候选必须继续返回 `EXPORT_FORMAT_UNSUPPORTED`。另一方面，已审核的正文仍需要可下载的内部工作稿，以便真实员工核对内容和定位排版问题。预览稿不得成为人工审定或正式交付文件。

## 决定

- `PREPARE_PREVIEW` 只固定已确认分析基线的原始格式事实与受控模板，不能把不支持的要求改写为“已满足”。不允许复用失效基线。
- 模板状态区分 `UNPREPARED`、`PREVIEW_ONLY` 与 `PREPARED`。`PREVIEW_ONLY` 只允许 `mode=preview` 的派发、生成与下载。
- `PREPARE_EXPORT`、`mode=candidate` 的派发和生成继续逐项校验强制格式。候选仍须通过原有版本、依赖、权限与审核门禁；预览产物保持 `PREVIEW` 状态，不可审定或正式下载。
- 界面把内部预览和正式格式校验分成独立操作，并在格式未满足时禁用候选生成。

## 权衡与失败处理

这允许提前检查正文和文档结构，但预览稿可能不符合招标格式，不能当作 A12 验收。原始格式事实及产物字节持久化，失败任务保留以供定向重试。模板或正文变更后，预览仍按现有精确引用与依赖规则判为失效。后续补齐目录页码能力时，应先以真实 DOCX/PDF 排版和人工检查证明，再扩展强制格式白名单；不得仅修改状态或跳过校验。
