## Frontend implementation

- Implemented exact published-version selection and preview before receiving a presales handoff. Historical releases without snapshots remain visible and unavailable. Release options and previews are protected against late responses after selection/workspace changes.
- Added a separate materials panel. Presales release summaries and knowledge pages render by source type; knowledge-page binding requires explicit applicability. In-flight knowledge-base/page reads are scoped to the active workspace, project, base, and page; close or scope changes abort/ignore late responses. Access-denied reads clear the in-memory preview. Command-level access denial also aborts sibling reads before clearing scoped project content and open drafts; late same-scope bodies and stale responses from a superseded project cannot repopulate the view.
- Added outline dispatch, candidate editing, save and confirm as separate actions; writing remains gated on confirmed outline. Per-chapter task status/retry, candidate comparison/adoption and manual editing use server-provided refs. Manual editing preserves block structure, unchanged image references, and chapter evidence metadata.
- Added route, workspace, tab and browser-close guards for dirty outline/chapter drafts. P2 409 errors retain the open chapter draft and instruct the user to reload and compare. Change-impact confirmation is available only to project approvers when the server supplies a ready proof envelope; access-denied responses clear scoped project content and drafts. Read-only members cannot adopt candidates.
- The writing view renders persisted assembled manuscript status, revision and chapter bodies, marks it for reassembly when current input refs differ, and keeps string- and object-shaped missing materials/unresolved items visible after adoption without exposing IDs. Content tables use semantic cells and their scoped styles cross the nested renderer boundary.
- P3 review and export actions remain unavailable.
