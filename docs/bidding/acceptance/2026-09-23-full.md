## 工程证据与边界

- 审核、受控 DOCX、审定及下载：Task1–Task3 已分别通过工程门禁和独立 Sol 审查。Task3 源版本 `4e0c4ce1`，181 项后端测试通过。其 HTTP 审定测试具有预置分析基线，不能代替从零建项的全链验收。
- Enterprise 审核与导出 UI：Task4 源版本 `12390925`，122 项 UI 测试及 lint、precision、类型检查、Enterprise 构建通过；空数据页面 1440 深色和 390 窄屏视觉通过。实际业务回读仍是部分验证。
- 原文与技能观察保留：源版本 `20499d90`，控制器记录 `98ae0d26`，61 个测试套件共 378 项通过，无失败、错误或跳过；Sol 第三轮审查通过。容量不足拒绝新的受控观察，不驱逐执行中的观察；工具正文中的控制标记不作为可信错误信号。
- Task5 当前新工作区分析子链：使用真实应用、认证、项目配置、技能加载、原文读取、任务执行及结果处理，仅替换模型供应商输出。四类分析执行，真实另一项目来源被拒绝为 `EVIDENCE_OUT_OF_SCOPE`；同一任务人工重试成功，数据库保留原失败和第二次尝试。该单项 focused 测试通过，**目录至正式下载及整组新回归尚未通过控制器验收**。
- 拒绝诊断：数据库任务错误保存 code/category 和 rejected_output；精确字段路径由真实验证器对已存原输出重放核对。字段路径目前不在 error_json 内，不能称完整字段诊断已持久化。

当前 Task5 未提交完成版本、未接受独立最终审查。本节的旧版测试计数不可充作 Task5 新版全回归结果。

从零建项的真实应用测试进一步定位到配置衔接缺陷，修复与最终门禁仍在进行：

- 内置技能在新工作区可被授权绑定，但分析、目录、写作、审核和导出派发使用工作区相等查询，导致派发拒绝。改为复用当前员工授权的精确技能解析；外工作区私有技能仍拒绝。
- 历史无版本评分目录没有升级，其实际固定 Schema 缺少服务端要求的 `criterionIds`。新增明确包版本并沿现有归档安装机制升级；现有项目固定文件与摘要不重写。技能升级、固定包和任务列表组合回归 32 项通过，尚非最终整组门禁。
- 任务列表数字 ID 的 `CAST AS VARCHAR(64)` 被实际 MySQL 8.0.46 拒绝为 1064；`CAST AS CHAR(64)` 查询执行通过。该探针为空业务库的 SQL 兼容检查，不能代替授权验收。
- 受控导出技能缺少 `bidding_export_document` 工具声明，真实图执行报工具不存在。按技能包声明修复并验证，不在测试中伪造工具绑定。

模型可控 HTTP 链路 focused 测试已通过：分析确认、目录、写作采纳、组装正文、章节和跨章节审核、FIX 后定向修订／采纳／新正文重审，以及实际导出工具生成候选、审批上下文、审批和正式下载。候选与正式下载均为 HTTP 200，字节与数据库原内容一致。最终整组回归仍在修复旧 slice fixture 的依赖与授权配置，不能把 focused 通过写成整组通过。

## 实际 DeepSeek 运行
