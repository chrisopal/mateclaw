从零建项的真实应用测试定位到以下配置衔接缺陷，修复已进入上述 392 项工程门禁：

- 内置技能在新工作区可被授权绑定，但分析、目录、写作、审核和导出派发使用工作区相等查询，导致派发拒绝。改为复用当前员工授权的精确技能解析；外工作区私有技能仍拒绝。
- 历史无版本评分目录没有升级，其实际固定 Schema 缺少服务端要求的 `criterionIds`。新增明确包版本并沿现有归档安装机制升级；现有项目固定文件与摘要不重写。技能升级、固定包和任务列表组合回归 32 项通过，最终整组门禁另见上述 392 项新鲜执行证据。
- 任务列表数字 ID 的 `CAST AS VARCHAR(64)` 被实际 MySQL 8.0.46 拒绝为 1064；`CAST AS CHAR(64)` 查询执行通过。该探针为空业务库的 SQL 兼容检查，不能代替授权验收。
- 受控导出技能缺少 `bidding_export_document` 工具声明，真实图执行报工具不存在。按技能包声明修复并验证，不在测试中伪造工具绑定。

模型可控 HTTP 链路已包含分析确认、目录、写作采纳、组装正文、章节和跨章节审核、FIX 后定向修订／采纳／新正文重审，以及实际导出工具生成候选、审批上下文、审批和正式下载。旧 slice fixture 的依赖与精确授权配置已修复，不以缺授权回退为允许。控制器本轮保留的真实测试读回清单包含 12 个任务、13 次尝试、20 个修订及全部八技能的固定版本／摘要／实际加载观察。候选与正式下载均为 HTTP 200，字节与数据库原内容一致。

整分支固定版本 `a00a8a07..8302c14e` 的 Sol 审核为 REQUEST CHANGES：新需求基线复用商务需求编号时，可继承旧待办的分类／解决状态。当前限定 `BiddingReviewService` 与 `BiddingReviewTest` 修复精确基线绑定，合入保持阻断；此前各任务的工程审查不代表该跨基线场景已通过。前端独立复跑售前／投标 14 个套件、122 项全部通过。
