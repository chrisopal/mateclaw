## 实际 DeepSeek 运行

隔离验收库保存了真实模型尝试，原业务库与其模型配置保持不变。

原配置 maxTokens=4096：项目 `0f32dfb5-6a1d-4119-8230-d4e648ee8a8e` 中基础信息成功；其他分析失败。观察保留修复后需求第三次尝试确实读取 schema 和全部 28 个来源块，仍保存未闭合 JSON，结果 `OUTPUT_INVALID`。不能根据输出长度或图结束信号判断供应商 finishReason；供应商原因未捕获，记录为 UNKNOWN。

只改变隔离副本输出上限为 8192 的比较：项目 `c2bfedee-a5b9-4ade-9507-ec4a4f3dc779` 中基础信息、废标项、需求分析成功；评分分析连续两次完整 JSON 均缺 `totalChecks[0].criterionIds`，被严格 Schema 拒绝为 `OUTPUT_SCHEMA_INVALID`。原配置仍为 4096。比较运行已经停止并保留离线备份；未以自动填补字段、放宽 Schema 或手工确认失败结果继续后续流程。

当前技能复验：从已停止的 8192 副本复制独立数据库并校验 SHA，使用独立技能根及 `8302c14e` 固定运行包。新项目 `89f002bc-e47c-473e-a43c-bbd359478ca3` 固定新评分／导出 1.0.1 包，原模型配置与历史项目包均不修改。新评分 schema 为 2433 字节并包含 `criterionIds`，导出声明受控工具。基本信息、废标项、需求均首次成功；评分首次以 `EXECUTION_INTERRUPTED`／`resultUnknown=true` 失败，不能解释成模型 Schema 再次失败。仅派发一次人工重试，第二次同为 `EXECUTION_INTERRUPTED`／`resultUnknown=true`；两次失败均保留，独立运行已停止并校验离线备份。原始 dispatch wrapper 继承的 `experimentVariable` 标签不是本次单变量事实，本次输出上限始终 8192。
