## P0 当前代码与设计落点

### T01 基线检查
读取分支 HEAD、git status、根级及目录级 AGENTS/CONTEXT、构建脚本、数据库迁移模式。核对本规格与当前代码差异，不覆盖用户未提交内容。
完成条件：记录 HEAD、实际集成点、基线测试/失败；工作分支不对 dev 或原语义分支强推。

### T02 能力与权限审计
检查 Wiki 上传/解析与可见性、语义候选/审核/Context、Agent/Skills/工具、Workflow/审批、文件/导出、审计是否可复用。不能只看 README 宣称完成。
完成条件：逐项写“已有实现/需适配/需新增/未验证”；明确 Workspace 与项目级边界；无第二套 Agent Runtime。

### T03 小范围 ADR

完成条件：设计无双写权威；定义 feature flag 与关闭行为、版本控制与幂等。

## P1 项目与资料骨架

### T04 迁移与领域模型
创建最小售前表与版本字段；关联 Wiki/Graph、负责人与档案。沿用 ID、时间、迁移和事务规范。
完成条件：全新数据库+升级数据库都能启动；禁用功能不丢原有数据；不创建不存在的外部模块表。

### T05 真实项目 API
创建/查询/编辑/归档售前项目、分页、资料绑定；调用现有工作区权限。所有写入控制 expectedVersion、operationId。
完成条件：重启回读、重复提交幂等、旧版冲突、跨工作区失败；不能仅前端假数据。

### T06 前端基础工作台
新增路由与菜单、列表和六页签；复用设计 Token、国际化、表格与证据侧栏。
完成条件：真实 API 驱动，未配置/空/失败/只读状态清晰，enterprise/classic 均不破坏。

### T07 资料与图绑定适配
绑定/创建知识库、精确本体版本和语义图；复用导入/证据链；有权限与解析错误提示。
完成条件：不重新实现 Wiki；上传+快照+证据可定位；无模型也能管理材料。

## P2 需求纵向闭环（首个可验收里程碑）

### T08 Context 组装器
实现任务范围绑定、PresalesContextProvider 与 Semantic/Wiki 适配，保存任务快照清单；处理中断、截断、未知时间。
完成条件：A 项目任务不默认读 B；新读取再鉴权；版本变化报 stale；不是所有历史聊天拼接。

### T09 S1/S2 与候选输出
按实际 Skill 格式安装客户理解/需求澄清方法，输出 Schema 校验，落 Context 草稿和候选工作项。
完成条件：示例事实/假设/建议分开，引用可由服务端核验；无证据不接受事实；失败不返回假成功。

### T10 需求工作台与 G1
实现证据展开、候选修订、澄清、现有语义审核入口、内部需求基线批准；权限和并发核验。
完成条件：不可绕过语义审核；G1 固定精确引用；基线修改创建新版本；没有客户回复不得显示“客户确认”。

### T11 P2 完整验收
用 SAMPLE_CASE 跑“创建→材料→Context→候选→澄清→审核→G1”，保存运行与浏览器证据。
完成条件：模型未配置测试与真实模型测试分开记录；首个可用里程碑不假称完整方案系统已完成。

## P3 匹配与方案

### T12 S3/S4 与匹配表
使用授权产品/案例 Wiki，实现版本化 Fit-Gap 和案例适用性。
完成条件：无依据=UNKNOWN；预测维护等例子不得被推成已支持；引用授权可追踪。

### T13 S5 与方案模型
目录先行、章节模型、需求覆盖、条件/风险/路线图、版本复制与差异；支持人工编辑。
完成条件：编辑不覆盖发布版；覆盖率确定性计算；没有需求基线仅生成 provisional draft。

### T14 方案 UI
目录导航、章节编辑/生成、引用和缺口侧栏、修订比较、保存状态/冲突处理。
完成条件：用户修订保留作者与依据；AI 重生成先新版本，不覆写未保存输入。

## P4 评审与成果

### T15 独立 S7 评审
独立任务上下文、确定性检查+模型检查、问题定位、整改复核。
完成条件：评审 Agent 不发布、不批准、不改方案；资料缺失不会判定“无风险”。

### T16 S6 与输出渲染
核对已有依赖后实现 MD/DOCX/PPTX 输出，结构化页稿、模板化可编辑文件、内部/客户视图、候选文件哈希。
完成条件：真实文件可打开/可编辑、没有溢出；没有导出库就新增小范围适配并测试，不伪称已有功能。

### T17 G2 与精确发布包
发布候选→审批→原字节发布；重校验基线、权限、证据、阻断项和文件摘要；草稿有独立标记/水印出口。
完成条件：V3 通过不批准 V4；待审文件不能经通用附件 URL 被未授权下载；重复发布不产生重复版本。

### T18 S8 与内部交接包
生成只含已授权精确版本引用的 HandoffPackage；含范围、Fit-Gap、风险/未知、决策与可访问成果。
完成条件：生成包不创建投标/合同/交付项目；缺失/不可见事实不虚构补齐；未来接收要重新鉴权。

## 验证命令注意

当前读到的 package.json 中 build 和 lint 引用 `scripts/check-snowflake-precision.sh`。[R7] 实施时先检查该文件是否存在、脚本是否仍相同，再运行标准 `pnpm build` / `pnpm lint`；不得删除检查后宣布通过。

若基线脚本缺失/失败：记录标准命令失败，同时可用显式 vue-tsc、vitest、eslint、vite 检查定位问题，但必须明确这不等于标准入口已通过。不要默认执行带 --fix 的全仓 lint 后将无关修改一起提交。

后端根据实际 pom/已有测试命令执行定向测试及打包；JDK/Node/pnpm 以仓库锁定要求为准。记录运行数据库和模型，不把 H2 验证写成所有数据库兼容通过。
