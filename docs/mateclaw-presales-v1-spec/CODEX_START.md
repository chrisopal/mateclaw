# 给 Codex 的启动任务

请在 `chrisopal/mateclaw` 当前 `codex/enterprise-semantic-core` 工作基础上，实现《MateClaw 售前解决方案工作台 V1.0》。本包审阅基线为 `d45d4abb64b46f248550e713ff77633f7c362bd6`；开始前重新读取 HEAD、工作树和仓库指令，不强行回退或覆盖用户改动。

## 本次范围

只做售前：项目档案、客户资料、Context 卡、需求/澄清、需求基线、能力/案例匹配、结构化方案、独立评审、Word/PPT/Markdown 输出和内部交接包。投标、合同、项目交付模块不实现，只预留文档定义的四个接口。

## 开始执行

依次读取 README、SPEC、SKILLS、CODEX_TASKS、ACCEPTANCE。先完成 T01–T03 集成审计，然后优先实现 T04–T11 的完整纵向链：

`创建售前项目 → 绑定资料/Wiki/语义图 → 提取 Context 和需求候选 → 证据与澄清 → 人工 G1 → 持久基线`

不要先画出六个充满静态数据的页面就声称完成。每一阶段必须有真实后端、持久化、权限与关键自动化测试。第一里程碑通过后继续 T12–T22；未完成的阶段明确保留，不伪造测试。

## 不可破坏的约束

- 复用 MateClaw 的身份、工作区、Agent、Skill、Wiki、Workflow、审批/审计和现有语义核心；不引入旧 PI/Fastify/SQLite 方案，不另起 Agent Runtime。
- 业务状态、语义事实、假设/AI 建议分开。Statement 的 accepted、内部 G1、客户确认是三件事。
- 已发布版本不可原地覆盖；G1/G2 必须绑定精确版本、用途和内容摘要。
- 当前来源治理主要支持 WIKI_RAW；结构化运营记录通过受控 Context 明确标识读取，不伪装成已接受语义事实。
- 模型不能接受事实、批准 G1/G2、发布客户版、自动外发或任意执行 SQL。
- 权限在服务端和真实来源入口校验；禁止仅用项目 ID、前端过滤或提示词做隔离。
- 主助手与独立评审任务分开；评审不能批准自己。
- feature flag 默认关闭，关功能不删历史；不损坏 enterprise/classic 两种 UI。
- 不合并主线、不强推、不部署、不清空数据库；这些操作需要单独明确授权。
