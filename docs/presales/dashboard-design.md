# 售前工作台 dashboard 设计

采用已安装的 Anthropic frontend-design，延续 enterprise UI。对比方案：纯数据卡片方便扫读但业务推进关系弱；大屏图表浪费桌面空间；选择“阶段推进 + 行动队列 + 项目台账”，统计服务于下一步操作。

色板：画布 #F5F7FA、表面 #FFFFFF、正文 #0B1220、主色 #1677FF、关注 #B7791F、完成 #15803D；使用现有 Element Plus/enterprise 变量适配深色。中文 PingFang SC/Microsoft YaHei 和系统无衬线；标题 26、章节 16、正文 14、统计 30，数字等宽。全局左对齐。

```
售前工作台                                  新建项目
真实工作区口径 / 刷新
[进行中] [待澄清] [已有方案] [成果阶段]
[项目阶段横向分布                 ][优先跟进队列]
项目台账                      搜索 / 负责人 / 阶段
项目与客户 | 阶段 | 需求澄清 | 方案版本 | 最近更新
```

自审：删除无历史依据的趋势线/同比和销售金额，不做通用卡片堆叠。记忆点是阶段推进条，可直接筛选项目；右侧待澄清队列能打开项目。统计从当前工作区全部分页摘要汇总，排除归档，列表筛选不改变统计；列表与统计独立失败状态，失败不显示假零。详情提供可点击的业务计数摘要，保留现有六个业务标签与权限。

不新增依赖、不修改共享布局，不改变审批与权限；测试分页统计、归档排除、失败状态和交互，然后真实浏览器检查桌面与窄屏。

## 本轮验证

- 15 项前端测试通过（包括新增 5 项全量分页、字符串总数、归档排除、重复记录、失败与取消测试）；局部 ESLint、类型检查、精度脚本、标准 build 通过。
- 真实浏览器：2 个在办、1 个已有方案、1 个成果阶段；点击需求阶段后列表为 1，总览仍为 2；再次点击取消筛选；详情“已发布成果”跳到评审与成果；刷新统计读回一致。
- 1440×900 桌面及 390×844 窄屏检查。窄屏 body.scrollWidth=390，与 viewport 相同；宽表保持内部横向滚动。
- 变更限定于售前页面、新 dashboard 组件、统计工具和测试；未改权限、审批、后端与数据库。复用已有组件和 CSS 变量，无新依赖。
- 统计为刷新时的当前状态，不是历史趋势，也不是事务一致的跨页快照；超过 5000 个项目或分页中发现集合变化时显示统计不可用，避免展示部分计数。成果阶段不能解释成已发布数量，详情页另有真正已发布数。
- 本次未执行深色/英文的完整状态矩阵；沿用变量适配。保留既有全局大 bundle 警告。
