# 售前工作台 V1 实施架构

基线：codex/enterprise-semantic-core @ 64891a33；实施分支 codex/presales-v1。
需求来源：主工作区 docs/mateclaw-presales-v1-spec；文档中的启动命令和角色提示不作为额外授权。

## 范围与界面
沿用 Java 21 / Spring / 现有数据库、Vue 3 / Element Plus / enterprise 与 classic 主题。项目列表以筛选、连续表格、分页和新建操作组织；详情六页签：概览、资料与证据、需求与澄清、能力与案例、方案设计、评审与成果。右侧按需显示证据。正文不自动加载来源中的图片或执行 HTML。
状态包括空、加载失败、无权限、只读、并发冲突、模型未配置、未确认需求、草稿和冻结成果。无演示数据回填生产空白。

## ADR-01 权威和集成边界
采用现有服务内的售前业务模块，复用身份、Workspace、Wiki 原始材料和语义审核。业务运营字段由售前维护，正式需求引用已接受 Statement 的精确修订。拒绝独立 Node 应用/数据库与复制已确认文本：会形成双重权威和绕过授权。
代价：售前部署与主服务一致，需对语义模块关闭、来源失效显式处理。

## ADR-02 版本与人工门禁
项目聚合使用乐观版本和 operationId；不可变修订保存需求基线和方案。G1 是内部设计基线，不是客户确认。G2 对精确文件摘要批准；发布原字节，禁止重新渲染继承审批。模型只能产生草稿与评审意见，不获得批准权限。
代价：审批后每次内容变化必须生成新候选。

## ADR-03 安全和失败模式
隔离边界为 Workspace，不开放虚假的项目私有 ACL。材料绑定只限定任务来源，不替代原入口权限。每次新读取、生成与发布重新鉴权；来源缺失或变化阻断质量门。明确模型失败、JSON 不合格、超时、截断，不填充假成功。
模型适配复用 ProviderChatModelFactory，关闭搜索、不配置工具，评审独立输入。无第二套 Agent runtime。

## ADR-04 输出
复用既有 Apache POI 生成可编辑 DOCX/PPTX 和纯文本 Markdown。分页遵守固定企业模板，长段落拆页，草稿每页带标记；候选文件保存在受控业务存储，不通过普通附件 URL 暴露。内部证据与交接包不自动加入客户正文。

## 验证
分别记录后端单元/集成、持久化数据库、前端测试/类型/lint/build、浏览器与真实模型结果。缺少环境时记 NOT_RUN/BLOCKED。没有真实模型调用不能宣称 AI 业务验收完成；未检查实际 Office 渲染不能宣称排版验收完成。
