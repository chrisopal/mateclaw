# 售前数字员工执行模型

用户已明确修正：数字员工是执行主体，工作台承接执行过程和人工决策。

保留项目、资料、精确版本、权限、幂等、人工需求确认与发布审批。替换售前页面的模型选择和直接模型调用，项目绑定 MateClaw 已配置员工，复用既有员工运行机制。员工负责资料分析、需求与澄清、能力/案例匹配、方案和成果草稿；人工补充员工提出的问题并继续任务。历史人工记录保留，不伪装成员工产物。

界面：项目档案选择负责员工；详情头部显示负责员工和执行入口；任务记录显示执行者/状态/结果；澄清区改为员工待补充信息，人填写答复与出处后可继续执行。无绑定/停用/模型不可用明确阻断，不能回退到直接模型或虚构成果。

业务用语：G1→确认本轮需求，G2→审批发布；客户确认、内部需求确认、语义事实审核保持区分。用户界面不出现 S1–S8 等技术编号。

执行边界：复用原员工运行与授权，任务来源固定在项目授权资料；工具范围必须服务器控制，提示词不是权限。员工输出不接受事实、不批准需求、不发布成果。重试不重复运行；执行失败/项目变化保留真实失败状态。真实模型未配置时只验证阻断与受控测试，不能宣称生成成功。

当前隔离验收库仅有领域本体建模师、内容工作室、推理分析师、通用助手，未替用户绑定不相关员工。真实售前员工模型执行尚未验证。员工绑定/输出投影由后端测试覆盖，不能替代真实模型端到端证据。

当前仅支持 native/react 员工；所选售前技能完整内容由服务端注入，其他绑定技能只展示目录。外部工具、自动跨项目记忆、Wiki/团队背景、模型降级链关闭；内置联网搜索模型拒绝执行。取消为停止接收结果，不承诺中断底层运行。未提交或部署到生产。
