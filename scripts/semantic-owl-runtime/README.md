## 后续测试约定

用户要求：后续本体模块的本地集成验收、智能体验收、UI 验收和重启回读，均使用此固定持久化库及上述服务。

- 测试前确认服务进程的实际 JDBC 路径和现有数据，不能以健康检查成功替代数据连续性检查。
- 使用独立验收工作区及带批次前缀的测试数据，记录创建的资源 ID；保留测试结果供刷新和重启回读。
- 只清理本次测试明确创建的资源；不删库、不清空业务表、不覆盖手工数据。
- Maven/Vitest 单元与故障注入测试继续用隔离测试库，不能把会重置数据库的测试套件直接指向本库；它们不能替代持久化环境验收。
- 历史验收脚本若引用已不存在的 fixture，应报告缺少数据并创建新的可追踪测试批次，禁止把空结果当作通过。
- 迁移或版本升级前先停止服务，再备份数据库并核对校验和。不要直接复制正在写入的 H2 文件作为备份。
