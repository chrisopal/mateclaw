## [HIGH] New commercial facts can inherit an old human disposition

**Location:** `mateclaw-server/src/main/java/vip/mate/bidding/BiddingReviewService.java:547–552`, especially line 549; consuming gates at 373–380 and 525–527; readback at 555–558.

`ensureHumanTodos` treats the model-supplied requirement `id` as a project-wide permanent identity and skips creation whenever any historical HUMAN_TODO with that object ID exists. The todo stores source refs but no exact analysisBaseline ref or commercial requirement snapshot/digest. A new confirmed baseline is a new revision (`BiddingAnalysisService.java:274–285`) and model clause IDs can legitimately repeat. New review dispatch therefore encounters an old classified/closed todo instead of creating an UNCLASSIFIED item for the new fact. `readHumanTodos` takes the latest row by that bare ID; approval only blocks OPEN items whose impact is unknown or technical. It neither verifies a current-baseline mapping nor revalidates closed/only-commercial classifications against the new fact. Repository invalidation cannot rescue this: HUMAN_TODO lacks the baseline dependency and `markNeedsReconfirmation` only changes CONFIRMED/SELECTED/HUMAN_EDIT statuses (`BiddingRepository.java:516–518`), not OPEN/RESOLVED.

**Concrete counterexample:** baseline A has COMMERCIAL `R1`; a real approver classifies it as only commercial (or classifies then resolves it). After an addendum or a human analysis edit, baseline B reuses `R1` for a changed delivery/qualification condition potentially affecting the technical response. Rebuild outline/chapters/manuscript and complete independent review. Dispatch skips B's todo because A's `R1` exists; the old nonblocking disposition is returned and approval-context/APPROVE_ARTIFACT can proceed without any human impact classification of B's fact. This violates the current-fact/version gate even though manuscript/review/artifact refs are fresh.

**Minimum repair:** bind each current commercial todo to the exact baseline and frozen requirement content/provenance (or use a stable content-addressed identity with equivalent exact checks). Reconcile current baseline requirements at dispatch/read/approval: a changed/reused clause creates a fresh immutable OPEN/UNCLASSIFIED obligation, never inherits a disposition based on bare ID. Preserve old todo revisions and decisions for audit; do not mutate historical pins or silently erase old unresolved obligations. Both `requireReviewed` and `approvalEvidence` must consume the same current-fact predicate; readback should distinguish historical obligations and avoid returning revoked old source evidence as current proof.

**Required regression:** extend the real source/analysis/HTTP review fixture in `BiddingReviewTest` (existing commercial classification flow around 278–319) or the provider-only `BiddingEndToEndTest`: classify/resolve A's COMMERCIAL R1, confirm B with the same R1 but changed text/evidence, rebuild and review, assert a new UNCLASSIFIED obligation and BLOCKED context/rejected approval; classify the exact new ref using B's evidence, then permit approval.
